# QR読み取り画面の表示方向

## 操作

- 前面カメラと判定できる場合、鏡のような左右反転表示を初期状態にする。
- 背面カメラ、向きが判別できないWebカメラは通常表示から開始する。
- 動きが合わない場合は、読み取り画面上部の「映像の左右反転」で切り替える。
- 手動で選んだ表示方向は、このブラウザーで次回も使用する。保存するのは表示方向の真偽値だけで、QR・職員情報・認証情報は保存しない。
- ブラウザーが設定の保存を許可しない場合でも、現在の画面では切り替えられる。

## 安全性

変更対象はカメラ映像のCSS表示のみ。QR解析は元の映像を使用し、出勤・退勤・ログインのトークン検証、権限、サーバー時刻処理は変更しない。枠と案内文は反転しない。

表示の切り替えはカメラの再起動や再送信を行わない。打刻・ログイン処理中は切り替えを無効にし、エラー後の再送信は「もう一度読み取る」の明示操作だけで行う。

- `npm.cmd run check`：型確認、225テスト、ビルド成功。
- `scripts/check-qr-camera-preview-ui.mjs`：26項目成功。
- 実際のZXing読み取り処理に、架空のQRを表示したCanvasの映像を入力して確認。左右両表示で出勤・退勤・ログインの原文トークンが1回だけ受け渡されることを検証した。
- 不正QR、再試行、処理中、カメラ権限拒否、設定保存拒否、終了時のカメラ停止、スマホ幅を確認。
- 外部通信・本番データ変更・実カメラ使用なし。768×1024と390×844の画面画像を目視確認済み。

確認用画面：`http://127.0.0.1:3014/tests/fixtures/qr-camera-preview.html?camera=front`

プレビューサーバーが停止している場合は `scripts/Preview-Operations.ps1 -NoOpen` で起動する。確認用画面は架空映像であり、実カメラや打刻・ログイン処理を利用しない。
