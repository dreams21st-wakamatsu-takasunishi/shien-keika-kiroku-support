# 児童の契約日・保管書類台帳

2026-10-15。管理者 `admin` と児発管 `manager` のみ。教室長・指導員への機能権限付与では開放しない。個人端末用の現場モードにも開放しない。

## 入口・初期登録

児童名簿の「契約日・保管書類」タブ、各児童の同名ボタン、既存児童の編集画面内の案内から開く。新規児童は通常の名簿登録後に設定する。契約日・モニタリング月は推測で補完せず、既存児童は未登録から始める。書類ファイルは保存しない。

契約日は公開の `ChildProfile` や通常の `loadWorkspaceData` に加えず、専用の保護された登録情報として保持する。一般職員向けの名簿読み込みで契約・保管状況・証明書名を配信しない。

## 確認枠

- フェイスシート、契約書類4点、個支原案・会議・本案：契約時。
- アセスメント、受給者証コピー、利用計画、別表：契約日起点で初回と毎年の各枠。うるう日・月末を補正する。実際の発行日を入力し、実物の保管確認を別に記録する。過去年を最新版で置き換えない。
- モニタリング更新月：毎年の月を複数選択。契約月は初回計画に集約し、その翌月以降から月別の原案・会議・本案・モニタリング枠を生成する。当月は月初から表示、月末を確認目安とする。
- 更新月の変更：適用日と設定revisionを履歴追加。初回以外は本日以前へさかのぼらない。月途中の変更は翌月以降に適用し、現在月・過去の枠を消さない。
- 必要に応じた計画：任意追加の計画ごとに独立したキーを採番。同じ場所の別計画の会議では充足扱いにせず、原案・会議・本案をひも付ける。
- 証明書：作成日不要。名称で複数登録。
- 契約書：利用契約書1部、重要事項説明書署名ページ1枚、肖像権使用同意書1枚、個人情報使用同意書1枚を別々に確認。作成日は任意。
- その他書類：契約内容報告書の提出控え等を必要に応じて名称で追加できる。

未入力・保管未確認・当月確認・保管確認済みを区別。契約日・更新月が不明な場合は「すべて揃った」と判定しない。実物確認済みは内容・署名・法令適合の保証ではない。

## カテゴリ別表示

「契約・同意書」「基本情報・アセスメント」「受給者証・利用計画」「個別支援計画・モニタリング」「証明書・その他」に分類し、カテゴリごとに色付き見出しを表示する。書類種別ごとに登録件数・保管確認件数・要確認件数を区別し、最新の実際の作成日（証明書等は登録名）を表示する。履歴の訂正前・取消済みの行を現在の登録件数には含めない。

登録済み書類も初期表示の対象とする。書類名を押して開くと、年別・更新月別の独立した入力欄を確認できる。カテゴリボタン・既存の書類絞り込み・未確認だけの表示を併用できる。未保存の入力がある書類は閉じられず、表示対象の切り替えも止める。表示切り替え自体はDBへ書き込まない。今回の表示整理にはDBの変更やデータ移行は不要。

カテゴリ整理後の追加検証：型検査・325テスト・ビルド成功。架空データによる画面43項目（カテゴリ絞り込み、最新作成日、証明書名、年度別履歴、未保存時の収納・絞り込み防止、390px幅）と既存マニュアル導線114項目を確認。画像付き操作手順・PDFも更新し、65ページ・24ページの全ページ描画と本文・画像・目次リンクを検証した。本番の書類データは変更しない。

## 公的資料との区別

年1回の上記枠は依頼された事業所内の管理ルールであり、すべての書類に共通する法定更新期限ではない。

[こども家庭庁・放課後等デイサービスガイドライン概要](https://www.cfa.go.jp/assets/contents/node/basic_page/field_ref_resources/32675809-3f98-486b-9c03-efc695ede0bb/842aaa30/20240710_policies_shougaijishien_shisaku_10.pdf)に基づき、放デイ自身のモニタリングが6か月以上確認できない場合は、相談支援の更新月とは別の確認として注意表示する。必要に応じた早期の見直しを妨げない。受給者証の有効期限と個支本案の保護者同意・保護者／相談支援への交付日も記録できる。

[北九州市の契約内容報告](https://www.city.kitakyushu.lg.jp/contents/29800090.html)は契約・変更・終了時の提出に関する案内として掲載する。全国すべての事業所で同一の手続・書式・年次提出が必要とは判定しない。[北九州市の障害児支援利用計画の説明](https://www.city.kitakyushu.lg.jp/contents/17600187.html)にある利用計画と、事業所の個別支援計画の周期を同一視しない。確認日2026-10-15。所在地の指定権者・支給決定内容の確認は別途必要。

## 保存・権限

`202610150006_child_document_register.sql` により設定履歴と書類履歴を新設。既存児童・支援記録・下書きは変更しない。

読み書きは独立RPC。RLSで同一事業所かつ有効な管理者／児発管に限定し、通常の認証ユーザーにはSELECTのみを付与する。直接INSERT/UPDATE/DELETEは許可しない。RPCも同じ条件を再確認する。書き込みは対象児童の行ロックで直列化し、設定revision・訂正先の現行状態・重複登録・日付等を検査する。

訂正は `replaces_id` 付きの新しい履歴、取消は `operation=void` の新しい履歴。既存行はイミュータブルトリガーでUPDATE/DELETEを拒否する。更新・取消で過去データを消さない。作成者名とサーバー登録時刻も保持する。認証ユーザー削除で台帳履歴が消えたり削除が妨げられたりしないよう、作成者は認証時に確認したID・名称の履歴スナップショットとして保持する。

再送は登録UUIDと内容一致、または設定の同一revision更新の一致によって冪等に扱う。応答を受け取れない場合にも二重登録を防ぐ。通信失敗時には入力を残し、児童・タブ・アカウント切替・再読込は未保存入力があれば停止する。書類名や保管場所・メモをAIへ送る機能は追加しない。実データのローカルキャッシュ、ファイルアップロード、自動削除は追加しない。
