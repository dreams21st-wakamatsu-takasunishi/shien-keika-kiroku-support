# 本人用QR：個人端末で表示、事業所端末で読み取り

## 毎日の操作

1. **個人端末**で職員ID／メールとパスワードを使ってログインします。ログイン状態が残っていれば再入力は不要です。
2. 個人端末モードの **「本人用QRを表示」** を押します。個人端末のカメラは使いません。
3. **事業所端末**で目的を選んで、個人端末の画面にカメラを向けます。

| 事業所端末で選ぶボタン | 結果 |
| --- | --- |
| 本人用QRでログイン | QRを表示した職員として事業所端末にログイン。打刻しません。 |
| 出勤を読み取る | QRの職員の出勤をサーバー時刻で記録。ログイン中の職員は変わりません。 |
| 退勤を読み取る | QRの職員の退勤をサーバー時刻で記録。ログイン中の職員は変わりません。 |

- 3つのボタンはログイン画面にあります。受付の事業所端末はログインしていない状態でも打刻できます。
- ログイン後は「出勤予定 → 打刻・実績 → 事業所で本人用QRを読み取る」から打刻用の画面を開けます。
- ログイン中の事業所端末を別の職員へ切り替えるときは、編集内容を保存してログアウトし、ログイン画面から読み取ります。
- QRは1回限りです。出勤とログインを続けて行う場合は、個人端末で「新しいQRを表示」を押してから次の操作を行います。
- 打刻後は事業所端末に職員名・打刻時刻が表示され、本人用QR画面にも結果が反映されます。ログインの結果は事業所端末で確認してください。
- 通信エラーで結果が不明なときは、本人用QR画面または勤務実績を確認してください。打刻時刻を変えるための再読み取りはできません。
- 事業所端末のログアウトでは、個人端末のログインを解除しません（端末単位のログアウト）。

## 初回の設定

### 個人端末

本人のアカウントでログインし、「個人端末」「所有職員が本人」「承認済み」として登録してください。職員名簿とログインアカウントの紐づきも必要です。初回はQRだけで個人端末にログインすることはできません。

### 事業所端末

管理者または児発管で通常ログインし、「出勤予定 → 打刻・実績 → 事業所で本人用QRを読み取る → 初回の事業所端末登録」を開き、施設共用端末として登録します。以前の玄関QR端末が承認済み施設共用端末なら、再登録は不要です。

登録に使った同じブラウザーで読み取ります。シークレットモードや保存データの消去、別ブラウザーでは再登録が必要です。カメラ付きタブレット、またはWebカメラを接続したPCが必要です。

本人用QRの表示元と読み取り元は、同じ事業所に所属する承認済み端末でなければ利用できません。未登録端末をQR操作だけで自動承認することはありません。

## 公開手順（本番未反映）

以前の変更が公開済みでも移行できるよう、既存マイグレーションは書き換えず **202609160002_personal_staff_qr.sql** を追加しています。既存の勤怠記録は削除・再作成しません。

プロジェクトフォルダで以下を順番に実行します。失敗した場合はそこで止め、解消後に続けてください。

```powershell
npx.cmd supabase db push
npx.cmd supabase functions deploy attendance-qr-login
```

その後、フロントエンドを通常のGitHub Pages公開手順で更新します。DB更新からフロント更新までの間、旧QR操作は利用できなくなります。業務時間外などにまとめて切り替えてください。通常のパスワードログインはそのまま使えます。

Edge Function名は互換のため `attendance-qr-login` のままですが、リクエストの `action` によりログイン／出勤／退勤を処理します。`verify_jwt = false` は未ログインの事業所端末から読み取るための設定です。QRの本人確認と端末の認可はサービス専用RPCで必ず検証します。

公開後は実機で、本人用QRの表示 → 事業所端末で出勤 → 新しいQRでログイン → ログアウト後も個人端末で表示可能 → 退勤、の順に確認してください。

## 安全性と制限

- QRは2分間有効、90秒で自動更新。再表示すると以前のQRは無効です。画面を閉じたとき・バックグラウンドにしたときも失効を要求します。通信できない場合も有効期限で失効します。
- QRに氏名・職員ID・パスワード・ログインセッションは含めません。ランダムな使い捨てトークンだけを含め、DBにはハッシュを保存します。
- 読み取り時に、本人のアカウント・名簿・個人端末・施設共用端末の利用状態と事業所一致を再確認します。
- 個人端末の利用時間制限、利用停止、初回パスワード設定を回避できません。
- 二段階認証を設定したアカウントは、ログイン時には従来の本人確認を使ってください。QRによる出退勤打刻は可能です。
- 同じQRを別の施設端末で再使用することもできません。出勤・退勤の二重打刻、出勤していない状態での退勤を拒否します。日付は日本時間の当日です。
- 有効なQRログイン認可は同じ職員につき5分間に5回までです。Auth側の交換失敗でも認可済みQRは使用済みとなります。
- QR操作はオンライン専用です。オフライン時に後から打刻時刻を送信する動作はありません。既存のPIN打刻・管理者への打刻修正申請は変更していません。
- QRは短時間でも本人確認情報です。スクリーンショットを共有せず、読み取り時以外は閉じてください。QRの転送による代理操作を完全に防止する仕組みではありません。
- QRを期限切れ整理する際も、読取端末・職員・操作・時刻の監査情報は残します。ログインの監査は「認可」の記録であり、その後のAuth通信の成功を保証する記録ではありません。

## ローカル検証

- `npm.cmd run check`：型チェック、全テスト、本番ビルド。
- `deno check --no-lock supabase/functions/attendance-qr-login/index.ts`：Edge Function型チェック。
- `deno test --no-lock --node-modules-dir=none --allow-read --allow-env --allow-sys supabase/tests/personal_staff_qr_test.ts`：隔離PostgreSQLで発行権限・本人紐づき・他事業所・失効・一度きり・既存勤務予定への打刻・二重打刻防止・旧方式の無効化・監査保存を確認。
- Playwrightスキルに従い、実コンポーネントとQR画像を使った模擬カメラで確認。375px、768px、1024px、1280px幅、タブレット縦横、カメラ許可拒否・終了、通信エラー・再試行、個人端末での結果表示を検証。本番通信・本番データは使用していません。

実機カメラと本番Supabaseを組み合わせた検証は公開後に必要です。
