# 第10実装単位: Dレッスン管理・文章課題とごほうびの作成

更新日: 2026-10-16

## 入口と範囲

ホームとメニューの「学習管理」を「Dレッスン管理」に統一する。保存済みメニュー設定の内部ID `learning` は変えない。

- 当日の取り組み、児童別進捗、課題の指定、Word確認、アカウント連携を同じ項目に集約。
- 専用権限がある職員には「文章課題の作成」「ごほうびの作成」を追加。
- 文章課題: 校舎別に作成、編集、複製、表示・非表示。タイトル、お手本、制限時間1〜60分、難度1〜5、対象学習グループを設定する。改行と既存の `{漢字|かんじ}` 形式を保持し、安全なプレビューを表示する。
- ごほうび: カスタムテーマの4色と名前、カスタム演出の絵文字1〜3個と名前を作成・編集・複製。ガチャ追加か、その校舎の現在の連携児童へのプレゼントを選ぶ。既存ごほうびの配布方法は変更しない。チケット名設定、コイン直接付与、リズム編集は今回の移行範囲外。

## データを保持する移行

`lesson_settings` の全体設定を上書きしない。初回表示では既存の文章課題・テーマ・演出を読み、初回保存時にその時点の内容を校舎専用 `lesson_campus_content` へ引き継ぐ。課題・アイテムのIDを保持するので、既存の `textRecords` と所持アイテムとの対応を切らない。他校舎・公開ユーザー・ゲストの設定は変更しない。

専用設定がない校舎はこれまでどおり全体設定を使う。専用設定の作成後はその校舎の教材一覧を使い、全体設定の後日の変更を自動合流しない。複数事業所に同じ校舎の有効許可がある場合や管理元が異なる場合は、表示・編集を停止する。連携許可の拡張や実児童の新規連携はこの機能の公開で自動実行しない。

Dレッスンの旧作成画面は公開版・未移行校舎の共通設定を維持するため削除せず「全体共通」と明示する。旧画面のCSV・管理操作まで完全移行したとは扱わない。

## 権限・保存・配布

- `manage_learning_content` を新設。管理者は利用可能、児発管・教室長には明示付与が必要。従来の課題指定・Word承認・アカウント発行から自動昇格させない。
- Dサポートの職員JWT、現在の事業所、承認端末・セッション条件と専用権限を取得前・送信前・応答後に照合する。ブラウザーからの事業所・職員・接続先指定を採用しない。
- Dレッスン側はサーバー間秘密鍵と `lesson_support_scopes` の専用許可を検証する。管理RPCはservice_role専用。児童は本人の信頼済み連携校舎だけをRLSで参照でき、教材・配布記録を直接変更できない。児童JSONの校舎書き換えで別校舎を読めない。
- 校舎単位のrevisionと全体設定取り込み時のfingerprintを照合し、同時編集・古い初回データによる上書きを拒否。操作UUID、職員、校舎、教材ID、revision、配布人数を監査に保存する。30回/15分の保存上限。
- 応答不明時は同じ内容・同じ操作UUIDで再試行する。既に別の変更があれば再取得が必要で、後の変更を巻き戻さない。画面を閉じた後の同一操作UUIDの復旧UIは今回未実装。既に保存された一覧を再取得して確認する。
- プレゼントは現在その校舎に有効連携している児童のみ。`lesson_reward_grants` に配布権を保存し、学習JSONを丸ごと更新しない。作成と配布記録は同一トランザクション。児童が開いていた旧画面から保存しても配布記録を消せない。
- プレゼントは新規作成時のみ配布する。編集・再試行で再配布せず、後から連携した児童に自動配布しない。配布済みアイテムは非表示操作でも回収・削除しない。ごほうびの非表示はガチャからの除外であり、所持者の使用取消ではない。
- 児童側は再ログイン・再読み込みで最新一覧と配布権を取得する。開きっぱなしの画面へのリアルタイム通知はない。別校舎への転籍に伴う所有物の表示継承は名簿・校舎同期の別工程。
- 校舎・職員・タブの切り替えでは古い応答と画面内編集を破棄。作成画面内の切り替え、アプリの主要メニュー移動・ホーム・新規記録・ユーザー切替・ログアウトとブラウザー離脱に未保存確認を設ける。別メニューへの移動後に編集下書きを復元する機能はない。
- 文章の準備画面、演出アイコン、お手本プレビューは文字をHTMLとして実行しない。テーマ色は6桁のHEXだけを許可。

## 展開順序

1. 両側の型・テスト・ビルド、Deno検査、画面試験を実施する。
2. `node scripts/check-lesson-content-storage.mjs --rollback-test`。追加スキーマと架空データの保存・再試行・競合・権限・配布を同じトランザクション内で検証し、全変更をrollbackする。
3. `node scripts/deploy-lesson-managed-content.mjs --apply-and-deploy`。Dレッスンの専用SQL、Dサポートのmigration `202610160001_lesson_managed_content`、3 Functionを先に適用する。既存の児童・Auth・全体設定・連携許可・役割設定は変更しない。
4. `node scripts/check-lesson-content-live.mjs --run-fictional-test`。隔離事業所2件・校舎2件・架空職員/児童だけでAPI・本人用RLS・直接RPC拒否・権限喪失・競合・二重配布防止を確認して削除する。実児童への試験配布はしない。
5. Dレッスン、Dサポートのフロントを公開更新し、配信版と両側の資産を確認する。新しい児童画面は追加テーブルの読取に失敗すると同期エラーとして止め、古い共通設定へ黙って戻さない。DBを先に適用する。

## 検証コマンド

- Dレッスン: `node scripts/check-managed-content.mjs`、`npm.cmd run check:release`、`deno check supabase/functions/support-managed-content/index.ts`
- Dサポート: `npm.cmd run check`、`deno check supabase/functions/lesson-managed-content/index.ts supabase/functions/lesson-learning/index.ts`
- 管理画面: `node scripts/check-lesson-content-ui.mjs --cli <Playwright CLI>`。localhost:3026の架空fixture、実Supabase通信は遮断。PC/390pxの画像、文章・テーマ・演出作成/編集/非表示、再試行、校舎/職員切替、不一致応答と取得失敗後の消去を確認する。
- 児童画面: `node scripts/check-lesson-content-student-ui.mjs --cli <Playwright CLI>`。localhost:5178の架空fixtureで実際のDレッスン表示処理を使い、課題の対象グループ/非表示、ガチャ/プレゼント、HTML実行防止、校舎切替、ガチャ重複防止を確認する。
