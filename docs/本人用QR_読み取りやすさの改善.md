# 本人用QRの読み取りやすさ

## 操作

本人用QRの表示画面で「読み取り用表示（QRを大きく）」を押すと、白背景の画面へ切り替える。職員名、有効期限、明るさ・距離の案内を残し、QRを画面内に収まる大きさで表示する。右上の×で通常表示へ戻る。キーボードではEscapeでも戻れる。

通常表示の「読み取れないとき」には次の案内を収納する。

- 暗い場合は画面の明るさを少し上げる。
- 白飛びしてQRがぼやける場合は明るさを少し下げる。最大に固定しない。
- 照明の映り込みを避け、少し傾ける。
- QR全体と白い余白が映るよう、少し離してゆっくり前後に動かす。

画面の明るさ設定の自動変更、画像への明るさフィルター、QR画像のダウンロードや共有は追加しない。

## 表示変更と安全性

- QR画像：720px、黒白を明示、画像内の白い余白を2から4モジュールへ拡大。4モジュールの目安は [DENSO WAVEの解説](https://www.qrcode.com/en/howto/code.html/index.html) を参照。
- 拡大しても同じ画像を使う。新しいQRの発行、トークン変更、期限延長は行わない。
- 期限切れ・使用済み・背景に移動した場合は通常表示と大きな表示の両方からQRを非表示にする。
- 大きな表示からの再発行にも、既存の端末状態・承認確認処理を使う。認証・権限・打刻・有効期限処理は変更しない。

## ローカル確認（2026-10-08）

- `npm.cmd run check`：型確認、228テスト、ビルド成功。
- `check-qr-readability-ui.mjs`：38項目成功。390×844、320×568、844×390、768×1024で目視確認。
- `check-personal-qr-device-ui.mjs`：20項目成功。承認前の発行不可、同じQRの拡大、期限切れ、使用済み、画面を離れた際の非表示を、実際の表示処理と架空応答で確認。
- `check-qr-camera-preview-ui.mjs`：26項目成功。表示方向の切り替え、実際のZXing解析、二重処理防止が維持されることを確認。
- 通常の黒白と、黒30・白100の架空低輝度画像は実際のデコーダーで解析できた。黒140・白235の架空高輝度・低コントラスト画像は解析できなかった。後者は性能保証の試験ではなく、限界を確認する診断結果として記録する。
- 実カメラ、実際の端末輝度・反射条件での検証は未実施。白飛びした情報や映り込みによる欠損の復元は、この変更では保証しない。
- 本番への反映は承認済み。公開処理の成功後、`node scripts/verify-qr-camera-preview-release.mjs <コミット短縮値>` で公開バージョン・表示機能・配信ファイルを確認する。実機での改善効果の確認とは区別する。
