# 第8実装単位: 一括課題の編集・停止

入口: Dサポート「学習管理 → 課題の指定 → まとめて指定 → 過去の一括指定 → 履歴を開く → 一括編集 / 一括停止」。対象は自分が一括追加した課題。個別編集・停止の入口も維持する。

## 操作

- 現在の課題を再取得し、児童・校舎・グループ・分野・ステージ・内容・期間・版番号を表示する。変更可能な児童だけをチェックして選択できる。自動で全員を変更しない。
- 元の課題が未作成、連携や所属の確認が必要、停止済み、個別変更済みを区別する。個別変更済みの課題を一括編集で上書きしない。停止済み課題の再有効化は本機能に含めない。
- 一括編集では変更後の分野・ステージ・課題名・内容・期間を設定する。初期値は取得した変更可能な課題から設定する。複数児童の現在値が違う場合も、児童別の変更前を確認画面に表示する。
- 一括停止では各児童の現在の内容・期間を保持し、有効状態だけをfalseにする。現在の課題を元の一括追加時の内容へ戻さない。
- 確認画面で変更後の内容（編集）または停止する各課題（停止）、対象児童・所属・変更前の版を表示する。内容確認チェック後に実行する。確認画面を開くだけでは課題を更新しない。
- 児童別に変更済み / 停止済み / 未完了と理由を表示する。画面を再読み込みしても変更・停止の履歴から同じ操作で再確認できる。保存済み対象は再送しない。「元の一括指定を開く」から現在の状態を取得して次の編集・停止を始める。
- 操作の停止・画面/職員切替による後続送信の中断は一括追加と同じ。送信済みの操作や既に保存した児童分を取り消す処理ではない。

## 安全境界と記録

- lesson_task_batchesにkind（create/edit/stop）とparent_idを追加する。元の追加操作の内容・作成結果を上書きせず、変更・停止ごとに新しい操作UUID、対象課題の固定UUID、変更前の課題・revision、変更内容、結果・日時を記録する。
- 元の一括追加の作成職員本人、同一事業所、在籍・端末承認・課題管理権限、現在の児童・連携revisionを確認する。他職員の一括指定の編集・停止や引き継ぎは未実装。複数の事業所や公開登録/ゲストをまとめない。
- Dレッスンlesson_support_task_changesにはservice_role限定で操作・課題・元の一括指定・担当職員・要求内容・適用結果のsnapshotを保存する。課題更新とこの結果保存を同じトランザクションで実行する。
- source保存では許可された本人・校舎・グループを再確認する。現在revisionが確認時revisionと、同じ元の一括指定で最後に適用したrevisionに一致する場合だけ更新する。個別編集・別操作との競合は同じ内容でも拒否する。
- source保存後にDサポートへの応答が失われても、同じ操作UUID・内容の再送では保存した結果だけを返す。同時再送でrevisionや監査を重複更新しない。後で個別編集された場合も、過去の変更・停止を再適用して巻き戻さない。
- Dサポートの完了記録も後着の失敗で未完了に戻さない。両DBをまたぐ全員同時確定・自動巻き戻しは行わず、部分成功を児童ごとに表示する。「処理済み」は操作適用の記録であり、現在の課題状態や児童の達成を保証しない。
- 古いクライアントが変更・停止を追加操作と取り違えて送信しないよう、実行時にkindを明示して照合する。
- 1操作100名まで、追加・編集・停止を合わせ職員15分10操作まで。履歴は本人の直近20操作。児童の取り組み・コイン・学習到達・Word承認・Auth・合言葉は変更しない。

- 型検査・247テスト・両アプリのビルド、Dレッスンcheck:release、両FunctionのDeno型検査。
- check-lesson-task-batch-changes-ui.mjs: 実Supabaseを遮断した架空画面で現在課題・明示選択・変更前後/停止対象確認・別の元操作への応答拒否・同一UUID再試行・部分競合・履歴再開・個別編集/停止済みの除外・再有効化防止・職員切替・1280px/390pxを確認する。既存の個別指定・一括追加も回帰確認する。

- 初回の本番API機能試験は通過したが、試験前後の学習JSON全件ハッシュが変化した。試験用のsource/名簿の残留0件を確認した。原因を断定せず、再試験では既存行・本人情報/アカウント対応・項目別のハッシュをメモリ内で照合し、通常利用の更新と区別する。児童名や値・秘密を検証ログに出さず、既存データを書き戻さない。
- 再試験は通過。既存行の本人情報・アカウント対応は不変、試験fixtureの残留は0件。並行更新された項目はcoins、globalMistakes、items、practiceLogs、totalKeysTypedのみで、学習関連の更新と切り分けた。既存運用行の追加は0件、原状書き戻しは行っていない。学習JSON全体の不変は主張しない。
