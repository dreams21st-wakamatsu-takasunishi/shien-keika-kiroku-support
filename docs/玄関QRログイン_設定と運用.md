# 玄関の出退勤QRを使ったログイン

## 職員の使い方

1. 自分の個人端末でアプリのログイン画面を開きます。
2. **玄関QRでログイン**を押し、カメラの使用を許可します。
3. 事業所の玄関端末に表示されている出退勤用QRコードを読み取ります。
4. その個人端末に紐づく職員としてログインします。パスワードの入力は不要です。

ログインしただけでは出退勤は打刻されません。出勤・退勤は従来どおり、ログイン後の出退勤操作で打刻します。
ログインと打刻は別々に扱うため、ログインに使ったQRを続けて打刻に使用できます。

## 初回・利用条件

- 初回は従来の職員ID／メールとパスワードでログインして、個人端末の登録・承認を済ませてください。
- 登録端末が**個人端末・承認済み**であり、所有職員と有効なログインアカウントが一意に紐づいていることが必要です。
- 管理者の承認省略設定があっても、QRログインでは未登録・承認待ちの端末を承認しません。
- 施設共用端末は誰が操作しているかをQRだけで判別できないため、QRログインの対象外です。
- 職員IDの利用停止、アカウント停止、端末の許可取り消し、個人端末の利用時間制限を回避できません。
- 二段階認証が設定されたアカウント、初回パスワード未設定、未確認のメール／SSOアカウントは従来のログインを使用してください。
- ブラウザーの保存情報を消した場合や別ブラウザーでは、端末を再登録する必要があります。
- 端末を他人と共有しないでください。端末の画面ロックを使用し、紛失時は端末・アクセス管理から利用許可を取り消してください。

## 安全対策・障害時

- QRの有効期限は既存の2分間、更新周期は90秒です。QRに個人名・パスワード・ログインセッションは含みません。
- 発行元の共用端末が承認済みであることと、発行元／個人端末の事業所一致をサーバー側で確認します。
- ログイン先の職員ID・メールをブラウザーから指定して変更することはできません。
- 同じQRによる同一個人端末のログインは1回限りです。他職員の端末は同じQRでログインできます。
- 同じ端末からの有効なログイン認可は5分間に5回まで。認可後の通信失敗でも使用済みになります。その場合は新しいQR、または従来のパスワードログインを使用します。
- ログイン認可の使用済み情報は、元のQRが既存の期限切れ整理処理で消される際に連動して消えます。長期監査記録ではありません。
- Supabase Authの一時的な認証情報はサーバー内だけで交換します。メール送信、パスワード変更、権限変更は行いません。
- 通信失敗・カメラ使用拒否・期限切れは画面内に表示されます。無限に再送せず「もう一度読み取る」で再試行します。

## 検証

- `npm.cmd run check`：型チェック・76件のテスト・本番ビルド。
- `deno check --no-lock supabase/functions/attendance-qr-login/index.ts`：Edge Function型チェック。
- `deno test --no-lock --node-modules-dir=none --allow-read --allow-env --allow-sys supabase/tests/attendance_qr_login_test.ts`：隔離したPostgreSQL互換エンジンで、未承認・失効・他事業所・職員停止・紐づき競合・期限切れ・時間外・再利用・レート制限・RPC権限を確認。本番DBには接続しません。
- Playwright：375／768／1280px幅、実QR画像を使う模擬カメラ、読み取り後のエラー／再試行／成功、カメラ終了、出勤・退勤の既存スキャナーを確認。
- 実機カメラと本番Supabaseを組み合わせたログインは、公開後に確認が必要です。
