# Dレッスン管理機能の移行: 第1実装単位

更新日: 2026-10-08

## 今回の実装

職員用「学習管理」に「児童別進捗」を追加した。対象は既に連携している教室児童のみ。

| 表示 | 取得元・扱い |
| --- | --- |
| マウス | mouseLevel: 保存済み到達数、M-1〜M-7、次の練習 |
| キーボード・ことば入力 | keyboardSequence: 現行カリキュラムの125ステージ。廃止ステージを除外し、確認テストの復習指定も次の練習に反映 |
| ビジョン | visionCleared: 20ステージ×3難度の保存済み状態 |
| Word学習 | wordProgress: 旧形式のclearedと現行形式のstatus=clearedに対応。承認済み状態の参照であり、成果物の確認・承認は既存のWord確認で行う |
| 最短時間 | examRecords: 保存されている正の秒数のみ。直近の結果や正答率とは別の指標 |
| 入力ミス | globalMistakes: キー別累計の多い10キー。期間内のミス数や診断結果ではない |
| 直近の取り組み | practiceLogs: 保存済みの練習履歴から日付をまたいで最新30件。欠落・保存期間を保証しない |
| アカウント保存設定 | 児童番号、Auth連携IDの保存有無、合言葉発行日時のみ。Authの存在・停止状態・合言葉の有効性は未検証 |

欠損・不正な進捗値を0や未実施に置き換えない。到達数は保管データからの表示であり、過去の管理者による到達状況編集を否定する証拠にはならない。
文章入力のベスト文字数・正答率、全期間集計、CSV・印刷レポートはこの実装単位に含めない。

## 安全境界

1. Dサポートのlesson-learningで職員JWT・承認端末・学習管理権限・現在の事業所を確認する。
2. 対象児童の在籍と有効なlesson_child_linksをRLS経由で確認する。ブラウザーから学習ID・校舎・権限の指定を受け取らない。
3. Dレッスンのsupport-learning-readはサーバー間秘密鍵を確認し、事業所・学習ID・校舎許可に加えsupport_child_id/support_link_idの結び付きを照合する。
4. sourceProjectRef・dataTable・studentId・campusId・childId・linkIdを応答契約で再照合する。元のuser_data JSON、Auth UUID、メール、合言葉、コイン、成果物URLを応答に含めない。
5. 読取後、Dレッスン側の許可とDサポート側の職員・児童・連携revisionを再確認する。変更・解除・失敗時に表示を消去する。

今回の処理は参照専用。アカウント作成、パスワード変更、児童名変更、学習履歴変更、SQL移行は行わない。

## 検証

架空児童のみで実施。本番の児童データをブラウザー試験に使用しない。

- Dサポート: npm.cmd run check（型検査、208テスト、ビルド）。
- Dレッスン: npm.cmd run check:release。
- Dレッスン: deno test supabase/functions/_shared/support-learning_test.ts supabase/functions/_shared/support-progress_test.ts（17テスト）。
- 両Edge Function: deno check。
- check-lesson-progress-ui.mjs: 進捗表示、欠損、再取得失敗、応答児童不一致、切替中の旧応答、未連携、職員切替、390px/1280pxレイアウト。
- check-lesson-task-ui.mjs: 既存の課題作成・編集・停止等の回帰確認。

ブラウザー試験はローカルViteの/tests/fixtures/lesson-learning.html専用で、実Supabase通信を遮断する。
scripts/check-lesson-progress-ui.mjsは--cliにPlaywright CLIのエントリーポイントを指定して実行する。

## 公開時の順序と未検証事項

この実装はローカル検証済み。本番公開・本番職員権限での動作確認は未実施。

1. Dレッスン: support-learning-readを再デプロイする。サーバー間認証を使う既存設定を維持し、必要なら既存運用通り--no-verify-jwtを指定する。
2. Dサポート: lesson-learningを再デプロイする。職員JWTを関数内で検証する既存運用設定を維持する。
3. Dサポートのフロントエンドを公開更新し、Pagesのデプロイ成功と公開版番号を確認する。
4. 本番の許可済み職員で、連携済み児童の進捗、別事業所の拒否、解除後の拒否を確認する。合言葉やAuthは変更しない。

既存のsupport_child_id/support_link_idが未設定なら取得を拒否する。許可を緩めず既存の連携確定・Wordバインド経路で整備する。
新しい権限・アカウント発行監査はまだないため、アカウント管理の移行完了とは扱わない。

## 次の実装単位

1. 専用の学習アカウント管理権限・監査ログ・サーバー間Functionを作る。新規作成と既存連携を分離し、連携だけのためにAuthや学習IDを作り直さない。
2. 新規発行・合言葉再発行に操作ID、二重実行防止、本人再確認、部分失敗の復旧を設ける。失敗後にAuthだけ残る状態も検出する。
3. ログインカードはアプリ内で表示・印刷する。既存合言葉はAuthから取得できないため、確認不能の値をカードに印字しない。平文の一覧保存を新設しない。
4. 具体的ステージの課題指定・児童画面からの移動・期間内実績を追加する。今日の課題の案内と利用制限は別機能として扱う。
5. 権限・機能・本番動作の同等性を確認してから、教室運用の重複メニューをDレッスンから段階的に整理する。公開ユーザー管理、教材、全体設定、復旧機能は移行対象を個別判断する。
