## 今回の実装

職員用「学習管理」に「児童別進捗」を追加した。対象は既に連携している教室児童のみ。

| 表示 | 取得元・扱い |
| --- | --- |
| マウス | mouseLevel: 保存済み到達数、M-1〜M-7、次の練習 |
| キーボード・ことば入力 | keyboardSequence: 現行カリキュラムの125ステージ。廃止ステージを除外し、確認テストの復習指定も次の練習に反映 |
| ビジョン | visionCleared: 20ステージ×3難度の保存済み状態 |
| Word学習 | wordProgress: 旧形式のclearedと現行形式のstatus=clearedに対応。承認済み状態の参照であり、成果物の確認・承認は既存のWord確認で行う |
| 最短時間 | examRecords: 保存されている正の秒数のみ。直近の結果や正答率とは別の指標 |
| 入力ミス | globalMistakes: キー別累計の多い10キー。期間内のミス数や診断結果ではない |

欠損・不正な進捗値を0や未実施に置き換えない。到達数は保管データからの表示であり、過去の管理者による到達状況編集を否定する証拠にはならない。
文章入力のベスト文字数・正答率、全期間集計、CSV・印刷レポートはこの実装単位に含めない。

## 安全境界

1. Dサポートのlesson-learningで職員JWT・承認端末・学習管理権限・現在の事業所を確認する。
2. 対象児童の在籍と有効なlesson_child_linksをRLS経由で確認する。ブラウザーから学習ID・校舎・権限の指定を受け取らない。
3. Dレッスンのsupport-learning-readはサーバー間秘密鍵を確認し、事業所・学習ID・校舎許可に加えsupport_child_id/support_link_idの結び付きを照合する。
4. sourceProjectRef・dataTable・studentId・campusId・childId・linkIdを応答契約で再照合する。元のuser_data JSON、Auth UUID、メール、合言葉、コイン、成果物URLを応答に含めない。
5. 読取後、Dレッスン側の許可とDサポート側の職員・児童・連携revisionを再確認する。変更・解除・失敗時に表示を消去する。

第1単位の処理は参照専用。アカウント作成、パスワード変更、児童名変更、学習履歴変更、SQL移行は行わない。

## 第2実装単位: Auth診断と確認済みログインカード

「学習管理 → アカウント連携」で、連携済み児童のAuth実在、本人用RLS対応、停止状態、教室用メール形式を確認する。一般メールAuthと教室Auth、校舎コードなしの旧Authを区別し、複数の正当な本人Authは削除・統合しない。矛盾や過剰件数は要確認としてカード表示を止める。

- 専用権限: manage_learning_accounts。管理者は利用可能。児発管・教室長は権限設定で明示的に付与する。manage_learning_linksやWord承認権限とは独立。
- 保存済み合言葉を取得する機能ではない。職員が入力した現在の合言葉を実Authで確認できたときだけ、画面内カードに表示する。確認用ログインは短い一時セッションを生成・破棄するため、Authの最終ログイン時刻は更新され得る。パスワード・本人用アクセス権・学習記録は変更しない。
- 合言葉は数値6〜12桁、児童番号は現公開版の1〜50に対応。公開版ログイン設定を変更する際は、支援側診断の仕様も同時に見直す。
- パスワード、メール、Auth UUID、JWTをFunction応答・監査・QR・ブラウザー保存領域に残さない。QRは校舎を指定したDレッスン公開URLのみ。
- source側は児童ごとに15分で5回、職員ごとに15分で20回まで合言葉確認を許可する。成功・不成功どちらも回数に含む。
- カードは10分で消去する。閉じる、児童切替、職員切替、別タブ移動、再取得時にも消去する。カードを印刷する際はDサポートの名簿・画面・操作欄を含めない。氏名は初期設定で印刷しない。
- サーバーで検証後、両側の連携とDサポート権限を再確認する。失効・監査保存失敗ではカードを返さない。source側では本人RLS対応と児童番号も検証後に再確認する。
- Dサポートlesson_account_audit、Dレッスンlesson_support_account_checksに対象・職員・操作・結果・日時を記録する。秘密や合言葉のハッシュは保存しない。

第2単位のサーバー更新と架空児童での本番API試験は実施済み。カードのローカルPC/スマートフォン表示とA4の1ページPDFを確認した。フロント公開時はscripts/verify-lesson-accounts-release.mjsへ公開コミットの短縮SHAを渡し、版番号・配信資産・機能収録を確認する。

- Dサポート: npm.cmd run check（型検査、214テスト、ビルド）。
- Dレッスン: 共通ヘルパーのDenoテスト27件、両アカウントFunctionのdeno check。
- check-lesson-accounts-ui.mjs: 専用権限、不一致拒否、画面内カード、QR、PC/390px表示、A4印刷、保存領域に秘密がないこと、閉じる・非表示・期限による消去、児童切替時の旧応答拒否。
- check-lesson-accounts-live.mjs: 架空児童の診断・一致確認・不一致拒否・5回制限、権限/在籍/別児童/解除後の拒否、操作監査、架空児童の元の合言葉での再ログイン、試験データ削除。

本番API試験の初回では、通常運用と並行してuser_dataの全件ハッシュが変わった。原状書き戻しは一切行わず、再試験ではレコード別・項目別のハッシュを比較した。1件のコイン・練習ログ等の更新があり、既存児童の氏名・生年月日・学習ID・Auth ID・児童番号・校舎の対応には変更がなかった。架空児童のパスワードで再ログインでき、学習JSONの一致も確認した。検証用のAuth、児童、連携、監査を削除して終了した。

## 第3実装単位: 連携済み児童のAuth発行・合言葉再発行

第2単位は公開版7f44057.186.1で配信済み。今回の第3単位では、学習管理のアカウント連携に発行・再発行を追加した。

対象は、既存のDレッスン学習ID・児童番号を持ち、Dサポートへ連携済みの教室児童のみ。Dサポートの未連携児童に新しい学習IDを作成する操作、児童番号の自動採番、複数Authの統合、一般公開ユーザーのAuth変更は含めない。

- 専用権限はmanage_learning_account_credentials。管理者は利用可能。児発管・教室長は明示付与が必要で、以前の確認・カード権限から自動昇格させない。
- 発行は保存済みAuth ID・本人用アクセス権がない児童のみ。番号重複、既存メールAuth、古いAuth ID、他児童へのアクセス権、複数Authなどがあれば拒否する。再発行は本人用教室Authが1件と確認できる場合のみ。既存Auth ID・メール・学習IDを保持する。
- 対象児童の氏名入力と確認欄を必須にし、操作ごとにUUIDを発行する。児童・職員・事業所・連携revisionをサーバー側で照合する。
- サーバーは連携秘密鍵と操作ID・学習IDのHMACから10桁の合言葉を生成する。合言葉・そのハッシュを操作表やブラウザー保存領域に保存しない。発行結果だけに合言葉を含め、カードを10分以内で消去する。QRは引き続き校舎指定URLのみ。
- Dサポートlesson_credential_operations、Dレッスンlesson_support_account_operationsに操作・対象・職員・段階・結果を残す。source表のAuth UUID・対象メールはservice_role限定でブラウザーへ返さない。
- 未確定操作がある間は同じ児童への新操作を拒否し、同じ職員・同じ操作IDで再開する。同時実行は3分のleaseで拒否する。通信失敗後は別の操作IDを作らず、履歴から同じ操作を再確認する。
- Auth作成/変更後、本人用RLS対応と学習JSONへのAuth ID・発行日時の追記をSQLで原子的に完了する。学習JSON全体の読み取り値を書き戻さず、現在行をロックしてこの2項目のみ更新する。取り組み、コイン、進捗、氏名、生年月日、校舎は変更しない。
- 完了操作の再確認は発行から24時間以内。同じ合言葉を返し、パスワードや発行日時を再変更しない。新しい再発行が完了していれば古い操作のカード再表示を拒否し、古いパスワードへ戻さない。
- Authと2つのDBは分散トランザクションではない。処理中の権限/連携変更や障害はカード返却を止めるが、既に行ったAuth変更は自動で巻き戻さない。Authだけ残った場合も消して作り直さず、同じ操作の段階から照合・再開する。
- 未確定操作の担当職員が退職・権限喪失した場合、連携自体を変更した場合、秘密鍵を変更した場合は管理者による調査が必要。別職員への引継ぎ再開、連携変更後の復旧、旧キー保管によるカード再生成はこの単位に含めない。既存のDレッスン管理機能はまだ削除しない。

検証は架空児童のみ。型検査・221テスト・ビルド、Deno共通テスト33件、PC/390px表示、カードの期限・児童切替・非表示時の消去、同一操作ID再試行を確認する。本番APIでは発行/再発行、古い合言葉の拒否、本人以外の児童データの拒否、番号/メール重複拒否、完了再実行、古い操作の拒否、Auth作成後の途中復旧、解除後拒否、秘密が履歴に保存されないことを確認する。既存児童の対応項目を試験前後に比較し、通常利用による学習更新は原状書き戻ししない。

公開確認はscripts/verify-lesson-credentials-release.mjsに公開コミットの短縮SHAを渡して実施する。次は、未連携児童への学習アカウント新規作成・校舎別採番・本人確認・連携までの一連の登録経路、監督者への復旧引継ぎを個別実装する。

## 第4実装単位: 未連携児童の新規登録

第3単位は公開版06a27e2.187.1で配信済み。第4単位は「学習管理 → アカウント連携 → 児童選択 → 学習アカウントの新規登録」に追加する。Dサポート名簿の氏名・生年月日を使い、許可済み校舎への学習ID作成、児童番号の採番、Dサポート・Word連携、Auth発行、画面内ログインカードまでを接続する。

- 利用にはmanage_learning_linksとmanage_learning_account_credentialsの両方が必要。確認・カードだけの旧権限から自動昇格させない。管理者は利用可能。児発管・教室長は明示付与する。
- 名簿の生年月日を必須にし、対象氏名の入力、既存アカウントの不存在、対象児童・共有先・説明同意の確認を要求する。公開校舎publicや未許可校舎には登録しない。
- 既存IDの連携入口は残す。過去に連携・登録履歴がある児童には別IDを作らない。Dレッスンに同名・同生年月日、または同名で生年月日未登録の教室データがあれば、作成せず既存アカウントの確認へ案内する。名前は空白除去・NFKC正規化して照合する。氏名が変わった既存アカウント等は自動判定できないため、職員による事前確認も必須。
- 学習IDは操作UUIDから生成する内部ID。校舎ごとに1〜50の空き番号を選び、既存学習データ・予約番号・教室Auth候補との衝突を避ける。番号不足は登録を止める。現在の公開ログインの番号上限は変更しない。
- 初期データはmouseLevel=0、keyboardSequence=0、コイン・練習ログ等は空。M-1をクリア済みにしない。既存児童の学習JSON、パスワード、Auth IDは新規登録では変更しない。
- source側で学習データ、アクセス許可、Word用のchild/link対応、登録履歴を同じSQLトランザクションで作成する。Dサポート側の連携とAuth発行用操作履歴も同じSQLトランザクションで保存する。Auth発行は第3単位の保護・復旧処理を再利用する。
- Dサポートlesson_student_registrationsにrequested/source-created/linked/completed/denied、Dレッスンlesson_support_registrationsに作成済み対応を保存する。合言葉やそのハッシュは保存しない。合言葉はサーバー生成10桁、カードは10分で消去し、QRには校舎URLだけを含める。
- 同じ職員・児童・校舎・名簿スナップショット・操作UUIDで再開する。通信失敗後や未確定履歴がある間は別の新規登録を止める。3分lease、職員15分10操作上限を設ける。完了カードの再確認は24時間以内、合言葉を再変更しない。
- 画面を再読み込みしても履歴から同じ操作を再確認できる。児童/職員切替・非表示後の古い応答は破棄する。登録成功後はカードを閉じるか期限が切れてから名簿の連携表示を更新する。
- 分散トランザクションではない。途中の権限喪失・校舎許可撤回・名簿変更では既に作成した学習IDやAuthを自動削除しない。担当者が再開できない場合の監督者引継ぎ・復旧画面は次工程であり、現時点では管理者調査が必要。既存のDレッスン管理機能をまだ削除しない。

デプロイ: node scripts/deploy-lesson-student-registration.mjs --apply-and-deploy。両SQLを事前にrollback検証し、Dサポートの新規migrationとDレッスンの専用SQLのみ適用する。既存連携許可は増やさない。両Functionは関数内のJWT/橋渡し秘密鍵検証を使い、--no-verify-jwtで公開する。

## 第5実装単位: 未完了の新規登録を管理者へ引き継ぐ

第4単位は公開版58747fb.190.1で配信済み。第5単位では、担当職員の退職・不在・権限変更などで再開できない新規登録を、同じ事業所の管理者が自分へ引き継ぐ。入口は同じ「学習管理 → アカウント連携 → 学習アカウントの新規登録」の操作履歴。

- 引き継ぎはrole=adminの在籍職員のみ。承認端末、学習連携管理・アカウント発行の両権限、同じ事業所・児童・許可校舎・名簿情報を照合する。児発管・教室長への自動権限拡張はしない。
- requested/source-created/linkedだけが対象。完了・拒否済み、3分leaseで処理中、名簿・校舎・連携が変わった操作は引き継がない。元担当者が現在も在籍していても、管理者が確認して引き継げる。元担当者を自動で再有効化する機能ではない。
- 氏名入力・対象確認・理由選択を必須にする。理由は担当者不在/権限変更/通信障害/その他確認済みの列挙値とし、自由入力の秘密が監査に残ることを防ぐ。引き継ぎだけではAuth作成・変更、カード表示を行わない。改めて確認して同じ登録操作を再開する。
- 操作UUID、学習ID、児童番号、source側の元作成者、HMAC生成条件は保持する。lesson_student_registrationsのexecutor_idとhandoff_revisionだけを更新し、元actor_idを上書きしない。引き継ぎ後は元担当者の同じ登録再開を拒否する。別管理者への再引き継ぎもrevisionを照合する。
- lesson_registration_handoffsに旧担当者・新担当者・日時・理由・revision・引き継ぎ要求UUIDを保存する。15分で管理者10回まで。同じ要求UUIDの再送は同じ結果、古いrevisionや後から別担当者へ移った要求は拒否する。登録完了時にはcompleted_byに実際の完了職員を記録する。
- source側の操作履歴にあるactor_idは不変の元登録担当者（操作照合用）であり、引き継ぎ後の発行・復旧実行者を表さない。サーバー間送信はその元登録担当者で既存操作を照合する一方、DサポートのJWT・現在のexecutor・在籍・権限・lease・名簿・連携を再確認する。実際の引き継ぎ・完了職員はDサポートの上記監査で追跡する。source側のactor_idを現実行者として表示しない。
- 元作成者が無効でも、引き継いだ管理者の現在の権限で、Auth発行前・Auth発行後の途中状態を再開する。既存Authを削除・再作成せず、作成済みの合言葉や学習JSONを書き換えない。Auth確認用の一時ログインにより最終ログイン日時は更新され得る。
- 登録完了は現在executorとleaseをSQLで再照合し、登録・発行の履歴を同じトランザクションで完了する。引き継いだ管理者の降格・無効化、期限切れ、児童や連携変更はカード返却を止める。旧「連携済み児童の発行」入口から登録操作の同じUUIDを使って回避することも拒否する。
- 通常の合言葉再発行の途中復旧・引き継ぎ、名簿情報が変更された操作の修正、校舎変更、連携revision変更、秘密鍵変更、source側完了から24時間超の操作のカード再生成は対象外。自動削除・巻き戻しは行わず、個別の管理者調査とする。Dレッスンの従来管理画面はまだ廃止しない。
