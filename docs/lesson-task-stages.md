# 第6実装単位: ステージ指定と期間内の保存実績

入口: Dサポート「学習管理 → 課題の指定 → 対象児童 → 課題を追加 / 編集」。分野、具体的なステージ、任意の課題名・内容、開始日・終了日、停止を扱う。

## 対応範囲

- マウスM-1〜M-7、現行キーボード・ことば入力125ステージ、ABC導入12ステージ、ビジョン20種類×3難易度、Word8ステージ。実際のDレッスン定義から同じカタログを作り、廃止ステージを除外する。
- 文章入力・タイピングゲームは分野指定を維持する。可変の教材・コースを固定ステージとして誤って登録しない。
- ステージ未指定の既存課題はそのまま編集・表示・停止できる。指定なしは従来の分野選択画面へ進む。
- 児童ホーム「先生からのかだい → このれんしゅうへ」から具体的なステージへ移動する。元のマウス到達、ABC導入条件・順序、キーボード順序、テスト前の復習、Word導入条件・前段階承認、ビジョンの難易度条件は維持する。
- 未解放なら分野の画面と案内を表示する。課題の指定による強制解放、別の練習の禁止、進捗上書きは行わない。

## 実績の意味

- 現在の課題の分野・ステージ・指定期間に一致するpracticeLogsの件数と最新3件を表示する。日時、結果の記述、入力数等の保存済み量を表示する。編集後は現行revisionの期間・ステージで再集計する。
- 日付境界はAsia/Tokyo。開始日と終了日を含む。重複したログIDは1件として扱う。他のステージ・分野・期間外の記録は除外する。
- 新しいマウス・キーボード・ビジョンの完了/中断、Wordのページ保存、先生確認による承認ログにはstageIdを保存する。児童側の正規化でもstageIdを保持する。
- 旧形式の記録でstageIdがないものは、具体的ステージへの対応を推測しない。期間内・同分野に該当する件数を「ステージを特定できない旧形式の記録」として集計対象外表示する。既存の分野指定課題は分野一致の記録を集計する。
- 保存件数・保存期間の制限があるためhistoryCompleteは常にfalse。0件は未実施の証拠ではない。作成前・停止後も指定期間に該当する保存実績は表示し、課題経由の操作かどうかは判定しない。重複期間の課題には同じ実績が表示され得る。
- 取り組みはクリア・課題達成・Word承認・正式な支援記録保存とは区別する。自動達成判定や支援記録の書き換えは行わない。旧履歴の補完や全件保証はしない。

## 保存・権限・配信

- Dレッスンlesson_learning_tasksに任意のstage_idを追加。既存行はnullのまま。RPCの楽観ロックと監査snapshotにstage_idを含め、同一再送と異なるステージへの変更を区別する。
- sourceサーバーが実カタログで分野・ステージの組合せを検証する。ステージIDをURLやコードとして実行しない。児童・職員ともログイン、承認範囲、現在のchild/link対応を維持する。児童に職員向け実績を返さない。
- 職員の閲覧には既存の学習管理権限、追加・編集・停止には学習連携・課題管理権限が必要。Auth・合言葉・既存学習進捗・実児童の対応表は変更しない。
- デプロイ: `node scripts/deploy-lesson-task-stages.mjs --apply-and-deploy`。source SQLをrollbackで検証して適用、Word承認関数2本はログへのstageId追加だけを更新。sourceのsupport-learning-tasks / student-learning-tasks、Dサポートのlesson-learningを再デプロイする。連携許可を変更しない。
- 両フロントを公開更新する。`verify-lesson-task-stages-release.mjs <Dサポート短縮SHA>`とDレッスン`check:public-latest`で配信を確認する。
