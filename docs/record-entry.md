# 支援記録の入力画面統一

2026-10-15

## 入口

ホーム、共通メニュー、記録状況の児童別開始、アシスタントの通常の記録開始は `useRecordEntry` を使用する。同じログインID・記録者ID・日付に入力中記録が1件なら再利用する。複数なら選択を要求し、児童が既に含まれる場合はその画面を開く。問い合わせ失敗時には新しい画面を作らない。

入力中の通常画面で「記録作成」を再選択しても再マウントしない。「この画面に児童を追加」で選択済みの児童を外さず追加できる。保存済み記録の再編集・修正依頼への対応は従来どおり独立し、統合対象外。過去記録の明示的な複製もその目的を維持する。

## 既存下書きの統合

自動統合しない。記録状況の「自分の記録をまとめる」、または入力画面の「分かれた自分の記録をまとめる／別日を開く」から、対象を複数選択し、児童名・人数を確認して確定する。最初に選択した下書きがまとめ先になる。

入力画面から開く際は共有保存を待ち、画面選択中は自動保存と編集を停止する。他端末・タブの入力も終え、共有保存が完了してから操作する。端末内の回答が共有データと異なる場合や未共有の下書きは、共有保存の完了を案内して統合しない。

`merge_own_record_drafts` は認証、同一事業所、本人、記録者、端末種別、同日、記録形式、期待revision、児童・回答の重複を検査する。キー順に行ロックし、まとめ先更新と統合元削除を1トランザクションで行う。失敗時はロールバックする。保存済み `support_records` は変更しない。児童ごとの回答・記録形式・入力位置、まとめ先のタブ順と現在位置を保持する。

## 検証

- `npm.cmd run check`：型・単体テスト・本番ビルド。
- `node scripts/check-record-entry-ui.mjs --cli <playwright-cli.js>`：架空データの実コンポーネントで入口統一、追加、統合・取消、スマホ、通信失敗、ユーザー切替を検証。
- `node scripts/check-own-draft-merge-sql.mjs <PGlite dist/index.js>`：実SQLをメモリ内PostgreSQLで実行。権限・端末制限、revision競合、重複、失敗時の完全ロールバック、保存済み記録が未変更であることを検証。PGliteは開発用一時ランタイムで、本番依存には追加しない。
- `node scripts/check-record-save-recovery-ui.mjs --cli <playwright-cli.js>`：既存の保存復旧・上書き比較の回帰確認。
- 公開後 `node scripts/verify-record-entry-release.mjs <短縮コミットID>`：公開バージョン、機能マーカー、手順書、実行アセットの応答を照合。実在の職員での統合は実行しない。

本人の入力中記録が複数のブラウザーで同時に新規作成されるケースまでは排他しない。次の開始時に選択・統合へ誘導する。古い入力画面の共有保存は既存の児童ロック・revision制御・引き継ぎ検知で保護する。これは複数職員の共同編集を同一の下書きへ自動統合する機能ではない。
