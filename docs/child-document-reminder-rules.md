# 保管書類の更新・追加案内

確認日：2026-10-19。対象は「児童名簿 → 契約日・保管書類」。管理者・児発管の既存権限を維持する。

## 判定ルール

| 手掛かり | 表示・確認 | 区分 |
|---|---|---|
| 契約日 | 初回書類・契約書4種類、未確認の案内 | 登録情報 |
| 契約日の周年 | アセスメント・別表等の年次枠、次回1か月前の準備案内 | 事業所の管理目安。全国一律の法定年次期限ではない |
| 受給者証の有効期限 | 1暦月前から受給者証と利用計画の別々の更新欄。期限当日は有効、翌日から期限超過表示 | 登録された期限を優先。案内開始日はアプリの目安 |
| 登録したモニタリング月 | 当月の原案・会議・本案・モニタリング枠、翌月分の準備案内 | 受給者証等の登録情報。月末はアプリの確認目安 |
| 放デイの本案・モニタリング作成日 | 保管確認済みの最終日を手掛かりに6か月ごとの見直しを案内。1か月前から表示 | ガイドラインの実施状況の確認。登録日だけで実施や適法性を保証しない |
| 本案の同意・交付日 | 保護者同意日・保護者交付日の未入力を確認 | その他の交付等の実施状況は職員が別途確認 |
| 生年月日・登録きょうだい | 本人・名簿上の最年長候補の誕生月を参考表示。有効期限不明時は該当月・前月に確認を案内 | 北九州市の取扱いを地域の参考として明示。期限への自動変換なし |
| 登録きょうだい | サービス利用状況・世帯の上限額管理の該当性を確認 | きょうだいの存在だけで提出義務や請求を判定しない |

年次の受給者証・利用計画枠は、有効期限が判明した後は未登録の周年枠を増やさず、期限基準の更新欄を使う。登録済みの周年枠はそのまま残す。作成・交付時期は自治体や相談支援へ確認する。

## 保存・履歴

### 確認案内の統合

- 不足の判定は `childDocumentReminders` に統一し、未使用の旧 `documentWarnings` は廃止。
- 同じ書類・同じ更新枠の不足項目は1回だけ表示する。初回の年次枠と契約時の枠は「初回書類」へ、受給者証更新と利用計画更新は同じ前回期限のカードへ統合する。
- 書類名、初回・更新月等の対象、未入力・未確認項目を本文に表示する。登録済みの作成日や同意日を不足として再表示しない。
- 6か月の実施確認は該当の不足書類がある場合は同じカードへ統合し、根拠となる日付も表示する。該当する不足がない場合の同日付の実施確認は1件へ統合する。
- 各不足行の「この欄へ移動」は対象の更新枠へ直接スクロールする。未保存の入力がある間は移動しない。
- 誕生月・きょうだいの参考情報は不足アラートとは別に収納する。二重にあった公的資料・運用説明は、確認案内の「判定の考え方・地域差について」へ集約する。

### データの扱い

個支本案は、作成日なし＝赤「未作成」、作成済みで保護者同意日・交付日の一方でも未入力＝黄「未交付・未同意」、両日付あり＝緑「交付・同意済み」で表示する。実物の保管確認は別で扱い、日付完了だけで保管済みにはしない。未交付・未同意の本案は未確認絞り込みでも表示する。

- 利用計画の更新キーは `extra:usage-plan-renewal-YYYY-MM-DD`。既存のRPC・履歴テーブルで保存でき、DB変更は不要。
- 受給者証更新と利用計画更新は独立。受給者証を先に保存しても、未登録・保管未確認の利用計画の案内は消さない。
- 元の作成日を新しい欄へコピーしない。登録・訂正・取消は既存の追記方式で保持する。
- 相談支援交付日の入力欄・未入力案内は表示しない。過去の値は履歴データに保持し、ほかの項目の訂正保存でも消去しない。
- 新しい入力欄・案内の自動表示は、DBへの書き込みや書類の自動作成ではない。
- 保存した利用計画更新は、元の受給者証が後で訂正・取消されても履歴を保持する。
- 誤登録は書類を展開して上部の「削除」から登録取消できる。対象の登録のみを一覧から外し、元の情報と削除履歴は保持する。自動枠や他の登録に必要な計画の枠は未入力に戻る。未保存の入力がある間は削除を無効にし、入力の消失を防ぐ。
- 姓・住所から家族関係を推定しない。明示登録されたきょうだいリンクのみ使う。事業所外のきょうだいの利用や自治体は台帳だけでは判定できない。
- 個人情報を外部検索・AI・参照資料URLへ送信しない。公的資料リンクは固定URLのみ。
