# Dレッスン連携: 第1段階の実装と確認

この文書の配備状況は第1段階の記録。追加したWord申請・承認・実児童運用は `Dレッスン連携_Word確認と実児童運用.md` を参照する。

更新日: 2026-09-30

## 実装範囲

- Dサポートのホーム・メニューに「学習管理」を追加。
- 「当日の取り組み」: 児童と日本時間の実施日を指定して、保存済みの練習履歴を取得。
- 「アカウント連携」: Dレッスンの内部IDを照会し、名簿の氏名・生年月日と学習側の情報を人が確認したうえで対応づける。
- 連携管理は管理者、または `manage_learning_links` を委任された管理職に限定。
- 連携・解除は競合確認と監査履歴を含むDBトランザクション。ブラウザーからの直接書き込みは禁止。
- 閲覧は事業所と既存の端末制約に合わせる。送迎専用の現場モードには入口を表示しない。
- Dレッスンの児童ログイン、学習エンジン、保存先、管理者・先生画面は変更・削除していない。

まだ実装していないもの:

- Wordの確認申請、Dサポートへの通知、職員承認・差し戻し、児童画面への結果反映。
- 個別課題・取り組み範囲の指定と、児童側での表示・利用制御。
- 支援経過記録のPC欄への下書き反映、進捗集計、教材・報酬・アカウント管理の全面移管。
- 名簿からの学習アカウント自動発行・連携許可管理。今回のID入力欄は移行期の管理者用であり、最終的な日常運用UIではない。

## データと権限

| 保存先 | 対象 | 役割 |
| --- | --- | --- |
| Dサポート | `lesson_child_links` | 名簿と学習IDの対応、確認職員、版、解除状態 |
| Dサポート | `lesson_link_audit` | 連携・解除の監査履歴 |
| Dレッスン | `lesson_support_scopes` | 連携を許可する事業所・校舎・テーブル |
| Dレッスン | `lesson_support_students` | 連携を許可する教室児童の内部ID |

校舎だけでは許可しない。児童が保存するJSONの `campusId` をアクセス権の根拠にせず、サーバー管理の児童別許可も必要とする。公開登録ユーザー・ゲスト・マスターは対象外。

2本のFunctionを経由する:

1. Dサポートの `lesson-learning`: 職員Authを検証し、事業所・端末・管理権限をDBで確認する。
2. Dレッスンの `support-learning-read`: 共通のサーバー専用秘密値と、事業所・校舎・児童別許可を確認して読み取りだけを返す。

共通秘密値とservice-roleキーをブラウザー、`VITE_*`、ログ、Gitに保存しない。両FunctionはゲートウェイのJWT検証を無効にしているが、処理内で上記の認証・認可を必ず実施する。

取得対象は本人確認用の表示名・生年月日・校舎IDと、日付に合う履歴のID・日時・分野・タイトル・結果・量。Auth ID、メール、合言葉、コイン、全ユーザーJSONは返さない。

履歴は既存の `practiceLogs` の保存範囲のみ。保存上限・保存期間・未同期・除外分野の影響を受けるため、`historyComplete` は常に `false`。0件でも「未実施」と判断しない。正式な業務記録として自動保存・自動承認もしない。

## ローカル検証

PowerShellでDサポートのフォルダーからそれぞれ実行する:

```powershell
npm.cmd run lint
npm.cmd test
npm.cmd run build
npm.cmd exec --yes --package=@electric-sql/pglite -- node scripts/check-lesson-database.mjs
deno check supabase/functions/lesson-learning/index.ts
```

DBテストは隔離したメモリー上のPostgreSQLで行い、実児童を参照・変更しない。RLS、事業所分離、端末制約、権限、二重連携、版競合、監査、直接書き込み禁止を検証する。

Dレッスンのフォルダーから:

```powershell
deno test supabase/functions/_shared/support-learning_test.ts
deno check supabase/functions/support-learning-read/index.ts
```

画面試験では架空データのモックを使用し、本人確認チェック、通信失敗時の古い履歴消去、児童切替、0件表示、解除、390px幅の表示を確認した。モック試験と実接続試験は別であり、実職員のブラウザー運用を確認したという意味ではない。

## 実接続の再試験

`scripts/apply-lesson-bridge.mjs` はこの2プロジェクト・試験事業所・校舎専用。一般的な本番配備コマンドではない。リンク先refを照合し、DB追加・秘密値設定・Function配備・一時招待/アカウント/架空児童の作成と削除を行う。実児童の連携許可が存在する場合は停止する。

再試験が必要なときだけ、Dサポートのフォルダーから明示的に実行する:

```powershell
node scripts/apply-lesson-bridge.mjs --apply-and-test
```

秘密値はCLI出力に表示しない。既に両側にある場合は変更しない。片側だけ存在する場合は勝手に再生成せず停止する。一時ファイルは終了時に削除する。処理を強制終了した場合は `output/lesson-secrets-*.env` 等と、表示された試験IDの残存を必ず点検する。

エラー時はまずFunction/SQLの設定と招待制約を確認し、既存の招待制、RLS、端末制約を解除して回避しない。

## 次の段階

Wordは「児童が確認申請 → Dサポートに担当者向け通知 → 職員が成果物を確認して承認/差し戻し → Dレッスンに反映」の経路で実装する。成果物の版・二重承認・取り消し・未通知の再送を設計し、承認済みと自己申告の練習履歴を区別する。

課題割り当ては課題カタログと利用許可の独立テーブルで実装し、既存の進捗・コインを上書きして範囲制御しない。後続機能の運用確認が終わるまで、既存のDレッスン管理画面は削除しない。
