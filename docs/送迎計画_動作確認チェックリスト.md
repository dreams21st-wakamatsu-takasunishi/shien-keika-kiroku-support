# 送迎計画・手動配車 動作確認チェックリスト

## 反映前のコマンド

PowerShellでプロジェクトフォルダへ移動して実行します。

```powershell
Set-Location -LiteralPath 'C:\Users\conta\Desktop\支援経過記録作成サポート'

npx.cmd supabase db push
npx.cmd supabase functions deploy optimize-transport-route
npx.cmd supabase functions deploy home-assistant
```

`GOOGLE_MAPS_API_KEY`は、既存の`optimize-transport-route`と共通です。新しいAPIキーの登録は不要です。

## 1. 児童・車両の基本情報

- [ ] 児童名簿で「通常の迎え先」「通常の送り先」を住所まで登録できる
- [ ] 迎え・送りそれぞれに送迎エリアを登録できる
- [ ] 曜日ごとの迎え基準、乗車予定、送り希望時刻を登録できる
- [ ] 祖母宅、学童、習い事などの追加送迎先にエリアを登録できる
- [ ] 兄弟には同じ兄弟グループ名を登録できる
- [ ] 車両に通常使用車・予備車・自家用車を設定できる
- [ ] 車両の総乗車定員を、車検証どおり運転者を含む人数で登録できる
- [ ] 配車時の児童枠が「総乗車定員－運転者1名－添乗職員数」で表示される
- [ ] 添乗職員を増やすと児童枠が減り、超過時に警告される
- [ ] 車両の使用優先順を数字で設定できる
- [ ] 自家用車を選ぶと「手動のみ」が初期設定される
- [ ] 予備車を「不足時のみ」に設定できる

## 1-A. 送迎マップ・優先エリア

- [ ] 事業所、自宅・親族宅、学校・学童、その他を複数選択して同時表示できる
- [ ] 「すべて」で全地点の表示へ戻せる
- [ ] 送迎エリアを名前と色で事前登録できる
- [ ] 円範囲を使わず、名前だけの送迎エリアを登録できる
- [ ] 必要なエリアだけ円範囲を補助表示できる
- [ ] 地図のピンを選ぶと、複数の送迎エリアを候補へ追加できる
- [ ] 上下ボタンで第1候補、第2候補以降の優先順を変更できる
- [ ] 同じ住所に重なる兄弟・同校児童へ同じ優先順がまとめて保存される
- [ ] 保存後、ピンと登録地点一覧に優先順が表示される
- [ ] 配車画面で、ピンに登録した優先エリアを確認しながら手動で便を組める

## 2. 翌月の基本予定

- [ ] 「本日の業務」から送迎を開き、「月間予定」を表示できる
- [ ] 「翌月を開く」で翌月をすぐ表示できる
- [ ] 「基本予定を反映」で定期利用曜日の児童だけが対象日に作成される
- [ ] すでに手動修正した日別予定が一括反映で上書きされない
- [ ] 月カレンダーに未作成・人数・要確認・確定が表示される
- [ ] 住所などが不足する日は「要確認」と表示される

## 3. 当日だけの変更と確定

- [ ] 対象日を選び、迎え先、迎え時刻、送り先、送り時刻を変更できる
- [ ] 迎え・送りを利用しない児童は個別に無効化できる
- [ ] 児童ごとの滞在時間を変更できる
- [ ] 兄弟を同じ便にまとめる設定を切り替えられる
- [ ] 下書き保存後、別端末にも変更が反映される
- [ ] 「送迎条件を確定」で対象日の表示が確定になる
- [ ] 確定後も管理者・児発管は必要時に修正できる

## 4. 長期休暇・自宅迎え

- [ ] 長期休暇期間を開始日・終了日で一括指定できる
- [ ] 指定期間の迎え方式が「自宅等への迎え」になる
- [ ] 児童ごとの迎え時刻欄が不要になり、事業所到着目標が表示される
- [ ] 自宅、親族宅など登録済みの迎え先が反映される
- [ ] ミニマップで自宅・親族宅の位置関係を確認できる
- [ ] 手動配車後の時間計算で、10時来所に間に合うか確認できる

## 5. 平日の学校迎え

- [ ] 一日配車画面が「迎え配車」と「送り配車」に分かれている
- [ ] 迎え対象児童が迎え時刻の早い順、同時刻ではエリア順に表示される
- [ ] 本日の利用予定児童の迎え先だけがミニマップに表示される
- [ ] 児童カードをドラッグすると、その児童の迎え先ピンが強調される
- [ ] 同じ学校・同じ住所の児童を位置関係を見ながら同じ便へ配置できる
- [ ] 「時間計算」で手動の乗降順を変えずに道路時間と到着時刻が反映される
- [ ] 計算後、ミニマップに選択便の道路ルートが表示される

## 6. 送り配車

- [ ] 「送り配車」へ切り替えると送り対象児童だけが表示される
- [ ] 本日の利用予定児童の送り先だけがミニマップに表示される
- [ ] 児童カードをドラッグすると、その児童の送り先ピンが強調される
- [ ] 「時間計算」で各送り先への到着時刻・移動時間・帰着時刻が表示される
- [ ] 車両定員を超えない
- [ ] 車両台帳の総定員から運転者・添乗員を除いた児童枠を確認できる

## 7. 手動修正

- [ ] 児童カードをドラッグして別車両・別便へ移動できる
- [ ] 便を追加・削除できる
- [ ] 児童の送迎先を当日だけ別の住所へ変更できる
- [ ] 上下ボタンで乗降順を変更できる
- [ ] 上下ボタンで並べた乗降順が「時間計算」後も維持される
- [ ] 兄弟を事情に応じて手動で別便へ分けられる
- [ ] 追加利用児童を検索して配車対象へ追加できる

## 7-A. ミニマップ・時間計算

- [ ] 欠席・利用休止中の児童はミニマップに表示されない
- [ ] 同じ住所の兄弟・同校児童は同じピンへまとめて表示される
- [ ] 地図未登録の送迎先件数が表示される
- [ ] 配車先または順番を変更すると、古い計算結果が自動的に解除される
- [ ] 便ごとに「時間計算」を実行できる
- [ ] 各児童へ「前地点からの移動時間」と「到着時刻」が表示される
- [ ] 便の走行時間・距離・帰着時刻が表示される
- [ ] 複数便を計算すると、便ごとに色分けされたルートを選択表示できる

## 8. 職員配置・ガントチャート

- [ ] 各便に運転者と添乗職員を設定できる
- [ ] 画面下部のガントチャートに送迎対応時間が表示される
- [ ] 同じ職員・車両の時間重複が警告される
- [ ] 未出勤・休暇中の職員を指定すると警告される
- [ ] 会議、研修など既存予定との重複が警告される
- [ ] 送迎中に事業所へ残る職員数が基準未満になると警告される
- [ ] 車両定員超過、住所未入力、運転者未設定が警告される

## 9. AIアシスタント

- [ ] 例「8月20日の迎えを13時15分に変更」で実行案が表示される
- [ ] 実行案に児童名、日付、迎え・送り、変更後時刻が表示される
- [ ] 承認前には日別予定が変更されない
- [ ] 承認後、対象児童・対象日だけが変更される
- [ ] AI変更後の日別予定は下書きとなり、配車再確認を促す
- [ ] すでに確定済みの便をAIが無断で変更しない
- [ ] 日付・方向・時刻が曖昧な指示は実行案にならない

## 10. API失敗時と複数端末

- [ ] Google Routes APIが利用できる場合は道路時間・距離・ルートが表示される
- [ ] APIが一時的に失敗しても、手動で組んだ配車内容は消えない
- [ ] 住所未入力の児童がいる便では時間計算を止め、対象便を明示する
- [ ] 1便の送迎先が10地点を超える場合は時間計算を止め、便の分割を案内する
- [ ] 別の管理端末で保存した月次予定・日別予定・配車がRealtimeで反映される
- [ ] 個人端末の現場モードでは、月次計画や全児童住所の編集画面を開けない

## 合格条件

迎え・送りの両方で、対象児童の漏れ、車両定員超過、職員・車両の重複、住所未入力がないことを確認し、「配車を保存」します。初回運用は自動提案をそのまま確定せず、必ず管理者または児発管が手動で最終確認してください。
