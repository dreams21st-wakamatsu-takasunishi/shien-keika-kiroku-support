# 送迎計画・自動配車 動作確認チェックリスト

## 反映前のコマンド

PowerShellでプロジェクトフォルダへ移動して実行します。

```powershell
Set-Location -LiteralPath 'C:\Users\conta\Desktop\支援経過記録作成サポート'

npx.cmd supabase db push
npx.cmd supabase functions deploy calculate-transport-matrix
npx.cmd supabase functions deploy home-assistant
```

`GOOGLE_MAPS_API_KEY`は、既存の`optimize-transport-route`と共通です。新しいAPIキーの登録は不要です。

## 1. 児童・車両の基本情報

- [ ] 児童名簿で「通常の迎え先」「通常の送り先」を住所まで登録できる
- [ ] 迎え・送りそれぞれに送迎エリアを登録できる
- [ ] 曜日ごとの迎え基準、乗車予定、送り希望時刻を登録できる
- [ ] 祖母宅、学童、習い事などの追加送迎先にエリアを登録できる
- [ ] 兄弟には同じ兄弟グループ名を登録できる
- [ ] 車両に通常使用車・予備車・自家用車を設定できる
- [ ] 車両の使用優先順を数字で設定できる
- [ ] 自家用車を選ぶと「手動のみ」が初期設定される
- [ ] 予備車を「不足時のみ」に設定できる

## 2. 翌月の基本予定

- [ ] 「本日の業務」から送迎を開き、「月間予定」を表示できる
- [ ] 「翌月を開く」で翌月をすぐ表示できる
- [ ] 「基本予定を反映」で定期利用曜日の児童だけが対象日に作成される
- [ ] すでに手動修正した日別予定が一括反映で上書きされない
- [ ] 月カレンダーに未作成・人数・要確認・確定が表示される
- [ ] 住所などが不足する日は「要確認」と表示される

## 3. 当日だけの変更と確定

- [ ] 対象日を選び、迎え先、迎え時刻、送り先、送り時刻を変更できる
- [ ] 迎え・送りを利用しない児童は個別に無効化できる
- [ ] 児童ごとの滞在時間を変更できる
- [ ] 兄弟を同じ便にまとめる設定を切り替えられる
- [ ] 下書き保存後、別端末にも変更が反映される
- [ ] 「送迎条件を確定」で対象日の表示が確定になる
- [ ] 確定後も管理者・児発管は必要時に修正できる

## 4. 長期休暇・自宅迎え

- [ ] 長期休暇期間を開始日・終了日で一括指定できる
- [ ] 指定期間の迎え方式が「自宅等への迎え」になる
- [ ] 児童ごとの迎え時刻欄が不要になり、事業所到着目標が表示される
- [ ] 自宅、親族宅など登録済みの迎え先が反映される
- [ ] 自動配車後、事業所から遠い児童を先頭として10時来所から逆算される
- [ ] 送迎エリアが同じ児童が、可能な範囲で同じ便になる

## 5. 平日の学校迎え

- [ ] 一日配車画面が「迎え配車」と「送り配車」に分かれている
- [ ] 迎え対象児童が迎え時刻の早い順、同時刻ではエリア順に表示される
- [ ] 「迎えを自動配車」で道路所要時間の計算中表示が出る
- [ ] 同じ学校・同じ住所の児童が可能な範囲で同じ便になる
- [ ] 兄弟グループが定員内で同じ便になる
- [ ] 学校から次の学校へ向かえる場合は同じ便にまとまる
- [ ] 次の下校時刻に間に合わない組み合わせは別便が優先される
- [ ] 学校へ早着した場合の待機を含めた予定時刻になる

## 6. 送り配車

- [ ] 「送り配車」へ切り替えると送り対象児童だけが表示される
- [ ] 「送りを自動配車」で同じエリアが優先される
- [ ] 施設から近い送迎先を先頭に、順次遠い送迎先へ向かう順になる
- [ ] 車両定員を超えない
- [ ] 通常使用車が優先され、予備車は座席不足時だけ使われる
- [ ] 「手動のみ」の車両・自家用車へ自動で割り当てられない

## 7. 手動修正

- [ ] 児童カードをドラッグして別車両・別便へ移動できる
- [ ] 便を追加・削除できる
- [ ] 児童の送迎先を当日だけ別の住所へ変更できる
- [ ] 上下ボタンで乗降順を変更できる
- [ ] 「順番固定」にした児童は再度自動配車しても便に残る
- [ ] 兄弟を事情に応じて手動で別便へ分けられる
- [ ] 追加利用児童を検索して配車対象へ追加できる

## 8. 職員配置・ガントチャート

- [ ] 各便に運転者と添乗職員を設定できる
- [ ] 画面下部のガントチャートに送迎対応時間が表示される
- [ ] 同じ職員・車両の時間重複が警告される
- [ ] 未出勤・休暇中の職員を指定すると警告される
- [ ] 会議、研修など既存予定との重複が警告される
- [ ] 送迎中に事業所へ残る職員数が基準未満になると警告される
- [ ] 車両定員超過、住所未入力、運転者未設定が警告される

## 9. AIアシスタント

- [ ] 例「8月20日の迎えを13時15分に変更」で実行案が表示される
- [ ] 実行案に児童名、日付、迎え・送り、変更後時刻が表示される
- [ ] 承認前には日別予定が変更されない
- [ ] 承認後、対象児童・対象日だけが変更される
- [ ] AI変更後の日別予定は下書きとなり、配車再確認を促す
- [ ] すでに確定済みの便をAIが無断で変更しない
- [ ] 日付・方向・時刻が曖昧な指示は実行案にならない

## 10. API失敗時と複数端末

- [ ] Google Routes APIが利用できる場合は「道路所要時間を反映」と表示される
- [ ] APIが一時的に失敗しても配車操作全体は止まらず、概算配車へ切り替わる
- [ ] 住所未入力の児童がいる場合は概算利用と情報不足警告が出る
- [ ] 1方向の地点数が24件を超える場合は概算へ切り替わる
- [ ] 別の管理端末で保存した月次予定・日別予定・配車がRealtimeで反映される
- [ ] 個人端末の現場モードでは、月次計画や全児童住所の編集画面を開けない

## 合格条件

迎え・送りの両方で、対象児童の漏れ、車両定員超過、職員・車両の重複、住所未入力がないことを確認し、「配車を保存」します。初回運用は自動提案をそのまま確定せず、必ず管理者または児発管が手動で最終確認してください。
