# 支援記録の期間別・分割読み込み（2026-10-26）

## 変更内容

- 初回の支援記録取得は、本日を含む直近90日と、日付にかかわらない「未確認」「要修正」の全件。確認待ち件数と修正依頼は古い記録も対象とする。
- 以前の承認済み記録を削除・非表示設定にするものではない。記録一覧で古い日付・期間を指定すると、その範囲を追加取得する。片側や両側が未指定の期間も明示選択に応じて取得する。
- 月間PDFは対象月の全児童分を取得してから、選択児童のPDFを作る。月を読み込んだ後は、その月にしか記録がない児童も選択できる。
- 記録状況の対象日、朝礼の前回支援の対象日も必要時に追加取得する。会議支援はAppの支援記録配列を受け取らず、独自サービスで参照するため、本変更で取得範囲を狭めない。
- デモのローカル保存モードは従来どおり。個人端末モードの共有記録・名簿取得禁止は変更しない。

## 分割取得

1回は最大200行。`record_date desc, id desc` のカーソルで次へ進む。offset方式は使わず、同じ日付が多数あってもIDで区切る。初期範囲とカーソル条件はANDで結合する。全ページで事業所条件・削除済み除外・日付条件を維持し、質問スナップショットと本文は省略しない。

サーバー設定が200行より少なく制限されている可能性があるため、通常の期間取得では短いページだけで終了とは判断せず、空のページまで取得する。ID指定の小さい再確認だけは正確な残件数を取得して終了を判断し、不要な空ページ通信を省く。件数上限のため「全件」と誤表示することを避ける。重複ID・不正な日付・途中のエラーを検出したときは部分結果を公開しない。

## 表示と出力

- 完了前は「確認中」とし、「記録なし」「未入力」などの確定表示を行わない。失敗時は再読み込みボタンを表示する。日付・期間は失敗後も変更できる。
- コピー・CSV・月間PDFは必要範囲の取得完了まで禁止する。
- リモートの記録一覧ではメモリ内件数を全履歴件数と表記せず、「選択期間・条件に一致」の件数とする。
- 支援記録の入力画面、保存・上書き比較・版照合・下書き同期は変更しない。

## 競合とプライバシー

- 期間取得はApp内のメモリだけで共有する。DB、localStorageやファイルへの新たなキャッシュ保存、AI送信はない。
- アカウント・事業所・権限・端末範囲が変わると取得状態を破棄し、旧リクエストを中断する。遅い旧応答も結果へ反映しない。
- 同じ範囲の同時リクエストを共有し、全利用箇所が離れた未完了リクエストは中断する。完了した期間は同じスコープ内で再利用する。
- 保存・削除・Realtimeで更新された版は古い応答で上書きしない。期間取得中に通知されたIDをメモリ内で追跡し、完了前にそのIDだけ最新状態を再確認する。未取得だった記録の削除通知も対象とし、削除前のページから復活させない。全期間をやり直さないので、別職員の保存が続く場合の負荷を抑える。
- 手動全再取得・再接続・変更ID不明の通知では期間の確認状態を無効化し、閲覧中の古い期間を取り直す。IDが分かる通知では完了済み期間を再取得せず、従来のID別更新を使用する。
- 未送信記録の表示は既存の職員別保留キューと合流する。

## 検証・制約

- `recordPeriods.test.ts`：90日、日付・うるう年・月末、サーバーの小さい件数制限、途中エラー、中断、重複、元の本文保持、保存・削除との競合。
- `check-record-history-ui.mjs`：実コンポーネントと実クエリビルダーを、架空1,205行・73行制限で実行。過去期間、失敗と再試行、コピー・CSV・月間PDFの制御、記録状況、朝礼、削除通知、アカウント切替、744px/390pxを確認。
- 従来の保存復旧・児童引継ぎ・タブレット・端末間同期の試験も行う。実在する児童・職員の記録は検証用に変更しない。
- 「処理時間の確認」の「選択期間の支援記録取得」で所要時間を確認できる。意図した期間変更による中断は失敗回数へ含めない。
- 未確認記録が多い場合や、他の29種データが大きい場合は初回が依然重くなり得る。何秒短縮するかは実端末の計測待ち。
