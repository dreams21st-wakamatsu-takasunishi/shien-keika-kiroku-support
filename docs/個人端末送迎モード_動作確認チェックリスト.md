# 個人端末送迎モード・共有端末 動作確認チェックリスト

## 事前反映

PowerShellでプロジェクトフォルダへ移動して実行します。

```powershell
npx.cmd supabase db push
npx.cmd supabase functions deploy staff-login
npx.cmd supabase functions deploy send-transport-notification
```

GitHub Pagesへ公開する場合は、動作確認後に通常のcommit・pushを行います。

## 1. 既存データの維持

- [ ] 既存の児童、支援記録、送迎便が削除されていない。
- [ ] 既存の承認済み端末が「登録端末」に表示される。
- [ ] 既存の事業所端末を「事業所共有端末」へ変更できる。
- [ ] 同じブラウザーを別の職員IDで使用しても、新しい端末申請が増えない。

## 2. 個人端末

- [ ] 個人端末を「個人端末」として承認する。
- [ ] 対象職員の職員IDでログインできる。
- [ ] ログイン後、送迎専用画面だけが表示される。
- [ ] 支援記録、記録一覧、児童名簿、設定、職員管理が表示されない。
- [ ] 別の職員IDで同じ個人端末へログインしようとすると拒否される。
- [ ] 設定した個人端末利用時間外にログインできない。
- [ ] 30秒以上ほかのアプリへ切り替えた後、個人PINによる本人確認が表示される。

## 3. 自分の送迎

- [ ] 運転者または添乗者として登録された当日の便だけが「自分の送迎」に表示される。
- [ ] 車両、担当者、児童、乗降場所、予定時刻、注意事項を確認できる。
- [ ] 「出発」を1回タップするとサーバー時刻が表示される。
- [ ] 児童ごとに「到着」を登録できる。
- [ ] 迎え便では「乗車」、送り便では「降車」を登録できる。
- [ ] 迎え便では「事業所到着」、送り便では「帰着」を登録できる。
- [ ] 同じボタンを素早く2回タップしても二重登録されない。
- [ ] 登録直後の「取り消す」で状態と表示が戻る。
- [ ] Googleマップを開くと、登録されている乗降場所が表示される。

## 4. 全体の送迎とカバー

- [ ] 「全体」で当日のすべての便を確認できる。
- [ ] 担当外の便は、担当者・車両・人数・進行状態だけが表示される。
- [ ] 担当外の便では児童名や住所が最初から表示されない。
- [ ] 「この便をカバーする」で確認画面が表示される。
- [ ] 承認後、対象便が「自分の送迎」に加わり、運行詳細を確認できる。
- [ ] カバー中は乗降操作を登録できる。
- [ ] 「応援を終了」後は詳細が再び非表示になる。

## 5. 通知とRealtime

- [ ] 端末Aで乗車を登録すると、アプリを開いている端末Bへ数秒以内に表示される。
- [ ] 端末Bを別画面にして戻っても最新状態になっている。
- [ ] 通知許可済み端末ではバックグラウンド通知が届く。
- [ ] ロック画面通知に児童名・住所・申し送り内容が表示されない。
- [ ] 「遅れています」が他端末へ反映される。
- [ ] 「応援が必要」が他端末で強調表示される。

## 6. オフラインと安全動作

- [ ] オフライン中は赤い警告が表示される。
- [ ] オフライン中の送迎操作は登録されず、成功表示も出ない。
- [ ] 通信復旧後に再読み込みされる。
- [ ] 端末を利用停止すると、表示中でも最長1分程度でログアウトされる。
- [ ] 操作した職員、物理端末、サーバー時刻が監査履歴に残る。

## 7. 共有タブレット

- [ ] タブレットを「事業所共有端末」として1回だけ承認する。
- [ ] 共有の指導員アカウントでは従来どおり記録者を選択できる。
- [ ] 支援経過記録を作成・保存できる。
- [ ] 別の職員が使用しても、端末承認申請が重複して作成されない。
- [ ] 管理者が共有端末を停止すると、そのタブレットから利用できなくなる。

## 注意

- 個人端末の送迎操作は通信接続が必要です。通信不能時は事業所への電話連絡を優先します。
- バックグラウンドPush通知には、既存のお知らせ通知と同じVAPID Secretを使用します。
- 個人端末では送迎に必要な情報だけを表示し、支援経過記録の入力には使用しません。
