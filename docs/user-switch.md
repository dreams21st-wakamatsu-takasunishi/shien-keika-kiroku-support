# 右上の職員名からのユーザー切り替え

2026-10-15。通常画面のHeaderに、職員名からの明示的な切り替え導線を追加。確認画面で現在のユーザーを確認し、「切り替えてログイン画面へ」で実行する。キャンセル・閉じる・Escapeでは認証状態を変更しない。ローカル試用では無効。

## 保護する内容

- 権限の切り替えは表示名の変更ではなく、既存の認証でログインし直す。施設ログイン、本人用QR、職員ID、メールの認証規則や端末承認を変更しない。
- 活動・指導案、施設業務、会議、研修設定の既知の未保存状態では停止し、先に保存するよう案内する。その他の配車・予定等も先に保存することを確認画面に表示する。
- 支援記録の入力中は、現在の回答を本人のローカル下書きへ保持し、キュー内の共有保存を待つ。期待revision・記録者IDを付けて最新の下書きを共有保存した後だけログアウトする。正式な記録の保存・承認・削除は行わない。競合・通信エラーでは切り替えを停止する。
- ログアウトは `scope: 'local'`。別端末で本人用QRを表示しているログインを解除しない。出勤・退勤は打刻しない。
- ログアウト失敗時に画面をローディングへ置き換えず、元の入力画面を維持する。再試行と取消が可能。
- 成功後はユーザー固有の画面状態をリセットし、利用者が明示した操作としてページを再読み込みする。前の利用者のメモリ内画面を、新しいログインへ引き継がない。元の利用者の下書きは既存の事業所・ユーザー別保存領域に残す。端末登録は削除しない。

## 検証

`npm.cmd run check`、`check-user-switch-ui.mjs`、`check-record-entry-ui.mjs`、`check-record-save-recovery-ui.mjs`、`check-contextual-manual-links-ui.mjs`。UI検証はlocalhostの架空データ専用で、実在する職員のログインやログアウトは実行しない。公開後は `verify-user-switch-release.mjs <短縮コミットID>` と `verify-contextual-manuals-release.mjs <短縮コミットID>` で公開アセットとマニュアルの一致を照合する。
