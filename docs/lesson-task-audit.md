# 第9実装単位: 管理者向けの事業所内一括課題履歴

更新日: 2026-10-15

入口は「学習管理 → 課題の指定 → 事業所の一括課題履歴」。在籍中の管理者だけが利用できる、閲覧専用の画面。

## 対象と表示

- 同じ事業所の全職員による一括追加・変更・停止の保存済み履歴。個別指定の履歴や、保存前の画面内下書きは含めない。
- 操作の種類、未完了あり / 全員処理済み、担当職員で絞り込む。退職・無効化した担当者も履歴から消さない。表示名は取得時点の職員情報であり、操作時点の氏名の証拠ではない。
- 作成日時と操作UUIDの降順、20件ずつ取得する。次ページの位置は最後に表示した行の日時（マイクロ秒を保持）とUUID。同時刻の操作も欠落・重複させない。新規操作や並行する結果更新を固定した全件スナップショットではなく、更新時点の読み取りである。
- 詳細に課題内容・期間・ステージ、変更前 / 停止対象、児童ごとの処理結果・未完了理由・処理日時を表示する。児童名は現在のDサポート名簿を使用し、名簿にない児童の氏名を過去データから補完しない。
- 「処理済み」はその操作の受領記録。現在の課題が有効か、後から個別変更されたか、児童が達成したかを保証しない。停止履歴から課題を再有効化しない。

## 権限と安全境界

- lesson-task-auditは職員JWT、get_lesson_learning_context、管理者専用判定を取得前後に照合する。所属の変化、無効化、降格、未ログインでは拒否する。
- can_view_lesson_task_audit / read_lesson_task_auditはauthenticated専用。DB内で現在の本人・在籍・role=admin・所属事業所・学習管理へのアクセス・manage_learning_linksを検証する。端末条件は既存can_read_lesson_learningの規則を継承する。ブラウザー指定の事業所IDや管理者フラグを信頼しない。
- SECURITY DEFINERの読取専用RPCから限定した項目を返す。元のlesson_task_batchesの作成者本人だけのRLS、mutation RPC、追加・変更・停止の権限は広げない。他職員の操作をこの画面から再開・引き継ぎ・再実行しない。
- source targets、児童の学習ID、児童のAuth UUID・メール・合言葉・練習JSONを履歴応答に含めない。Dレッスンへの通信や学習データ更新も行わない。職員UUIDは担当者絞り込み用に使用する。
- 取得失敗・応答の事業所/操作/絞り込み不一致では旧結果を破棄する。職員・事業所の切り替えで画面を破棄し、遅い旧応答を表示しない。画面結果をlocalStorage等へ保存しない。
- 管理者向け入口の判定取得に失敗した場合は入口を隠す。追加機能の判定障害だけで既存の連携一覧を利用不能にはしない。

1. `node scripts/deploy-lesson-task-audit.mjs --apply-and-deploy`。migration 202610150002をrollback検証後に適用し、lesson-task-audit / lesson-learningを更新する。Dレッスン側のDB・Function・児童・Auth・合言葉は変更しない。
2. migration番号と機能名の一致、専用DB関数の実在を確認してからFunctionを更新する。別機能が同じ番号を使用している場合は中断し、上書き・誤ったスキップをしない。PostgRESTへ定義再読み込みも通知する。
3. `npm.cmd run check`、両FunctionのDeno型検査、lesson-task-audit.test.mjs。
4. `check-lesson-task-audit-ui.mjs --cli <Playwright CLI>`。実Supabaseを遮断した架空画面で、絞り込み・前後ページ・変更前表示・閲覧専用・別事業所応答拒否・取得失敗後の消去・職員切替時の旧応答破棄・1280px / 390pxを確認する。既存個別課題と一括変更/停止も回帰確認する。
5. `node scripts/check-lesson-task-audit-live.mjs --run-fictional-test`。本番DBの新しい隔離試験事業所2件と架空職員3名だけを使用する。23件の同時刻履歴を2ページで取得、別担当者閲覧、操作/処理状況/担当者の絞り込み、別事業所・未ログイン・無効・降格後の拒否、直接RPCと元テーブルRLS、他職員の実行権限がないこと、履歴・受領記録の不変を確認する。試験事業所・履歴・職員を削除し、実児童やDレッスンを試験に使用しない。
6. 公開更新後、`node scripts/verify-lesson-task-audit-release.mjs <短縮SHA>`で公開版・資産応答・新旧機能の収録を確認する。公開配信確認、本番の架空API試験、ローカル画面試験を区別する。

初回の本番API試験では既存の202610150001（merge_own_record_drafts）との番号重複による専用関数の未適用を検出した。試験用データは削除し、202610150002へ変更して適用確認を強化した。既存migrationの書き換えは行っていない。

## 残工程

| 工程 | 現状・方針 |
| --- | --- |
| 他職員の一括課題の引き継ぎ・復旧 | 今回は閲覧のみ。元担当者・現在の実行者・操作revision・理由・監査と、source受領記録を保持する復旧設計が必要。閲覧できることを実行権限と混同しない |
| 通常のAuth発行・合言葉再発行の管理者復旧 | 新規登録の管理者引き継ぎは実装済み。通常発行/再発行の未確定操作の引き継ぎは別途対応 |
| 名簿情報・校舎・学習グループの同期 | 自動上書きは未実装。変更前後の比較、本人確認、校舎の許可・番号/Auth候補の衝突、Word/課題への影響を個別確認する必要がある |
| 成績レポート・CSV・印刷 | 児童別進捗、期間内の保存済み実績は表示済み。保存期間・欠落を明記したレポートへ進める |
| Dレッスンの重複メニュー整理 | 同等の権限・運用・復旧を確認後に段階的に整理。現時点で管理画面を削除しない |
| Dレッスンに残す全体管理 | 公開ユーザー管理、教材・リズム素材、全体設定、バックアップ/復元等は一律移行せず個別に判断する |

停止済み課題の一括再開や、個別変更された課題への強制上書きは、安全上の未実装事項であり、移行完了のために自動追加しない。
