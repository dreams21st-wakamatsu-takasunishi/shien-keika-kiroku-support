# Tiro会議支援の実装と確認

## 実装範囲

児童1名につき1会議案件を作成し、参加者・読み・所属、固有名詞、議題、確認事項を入力する。Tiroの文脈欄向け短文と事前情報シートをプレビュー、コピー、保存できる。会議中は議題ごとの状態、要点、決定、担当、期限を記入する。会議後はTiroのスクリプトまたは要約を取り込み、原文を残して修正版を版管理する。会議結果を確認後、会議由来の支援経過を作成、提出、差戻し、確認済みにできる。記録一覧には会議由来の記録を別区分で表示する。

録音はTiro側で開始する。アプリは録音状態を自動取得しない。Tiro API接続、話者の自動識別、個別支援計画への転記は含まない。

## 保存と権限

- `meeting_cases` に案件と構造化した事前情報・進行メモ・会議結果を保存する。
- `meeting_transcripts` は追記のみ。修正も新しい版として保存し、原文を上書きしない。
- `meeting_progress_records` は日々の `support_records` と別の表。出欠・間食・サービス提供時間を持たない。
- `meeting_export_events` にTiro向けコピー・ファイル保存の**試行**を記録する。ブラウザやOSでの最終的な貼付・保存完了までは確認できない。
- 案件を読めるのは作成者、指定された職員、`review_records` 権限者。個人端末の送迎専用利用からは会議データを取得しない。
- 個人端末からの書込みは既存の承認端末検証関数で拒否する。変更の競合は `revision` で検出し、相手の変更を自動上書きしない。
- 承認済みの会議由来記録と、その元になった会議案件をロックする。修正が必要な場合は別途訂正運用を設計する。

## 本番導入前に必要なこと

1. 事業所内で録音・Tiroへの情報提供の説明方法、同意の記録方法、保存期間、アクセスできる職員を確認する。
2. バックアップと復元手順を確認してから、`supabase/migrations/202609290001_tiro_meeting_workflow.sql` を対象Supabaseへ適用する。
3. 作成者、指定職員、指定外職員、確認権限者、個人端末の職員IDで、閲覧・編集・取込・承認の可否を確認する。特に指定外職員が案件・原文・記録を取得できないことをDB側で確認する。
4. 架空の児童データで、準備 → Tiro向け出力 → 会議メモ → 原文取込 → 誤変換修正 → 結果確認 → 記録提出 → 差戻し → 再提出 → 承認 → PDF保存を通す。
5. Tiroの実際の利用プランと画面で文脈欄、参照ファイル、スクリプトの取り出し方を再確認する。
6. 限定運用の結果を確認してから公開する。`main` へのpushはGitHub Pagesの公開処理につながるため、ローカル確認だけを公開済みと扱わない。
