# 記録保存・上書き比較の確認

## 変更内容

- 児童ごとの「○○・1名分のみ保存」は、その児童だけを保存し、入力中の児童・下書きから取り除きます。他児童の回答と入力位置は維持します。
- 下書きの古い自動保存を先に終え、保存した児童を共有下書き・端末内の下書きから除いた後に、記録一覧へ移動します。
- 同じ児童・日付、または編集中の記録が既に存在するときは、最新の保存済み記録と保存予定の記録を並べて表示します。変更のある項目は黄色です。
- 複数児童を上書きする際は、児童を切り替えて全員分の比較確認にチェックします。確認済み記録は上書きできません。
- 比較後に別端末が記録を変更した場合、既存のバージョン検査で上書きを止めます。再度保存を押すと、最新内容で比較し直します。

## 操作確認（テスト用児童・記録で実施）

1. A・Bの2名分を入力し、確認画面でAの「1名分のみ保存」を押します。
2. Aの保存完了と残り1名の案内が表示され、Bの入力内容が残ることを確認します。
3. 記録状況へ戻ると、Aが保存済み、Bのみが入力中になっていることを確認します。
4. Bの入力を再開して保存し、入力中の下書きが残らないことを確認します。
5. 保存済み記録を編集し、保存ボタンから比較画面を開きます。左右の記録者・出欠・本文・詳細を確認します。スマートフォンでは「保存済みを見る」「保存予定を見る」で移動できます。
6. 「上書きせず入力に戻る」を押し、既存記録が変わらず、入力中の内容も残ることを確認します。
7. 再び比較し、変更内容を確認したチェックを入れ、「比較した内容で保存する」を押します。同じ児童・日付の記録が増殖せず、既存記録が更新されることを確認します。

## 通信失敗時

- 最終保存は、通信して保存済み記録を確認できる状態で実行します。通信失敗時に未確認の上書きを自動送信することはせず、入力画面を残します。通信復旧後に再度保存してください。
- 記録は保存できても下書き整理に失敗した場合、保存済みであることを表示して「入力中一覧の更新を再試行」を出します。このボタンは記録を再保存しません。
- 下書き整理の直前に別職員から児童が引き継がれた場合は、更新競合として止めます。再試行時に最新の下書きから整理し直し、引き継いだ児童を維持します。

## 開発環境での検証

- `npm.cmd run check`：型検査・自動テスト・ビルド。
- 架空データと通信モックで、1名保存・最後の1名・旧自動保存との競合・上書きキャンセル・複数児童の比較・確認済み保護・保存失敗・下書き整理失敗と再試行を確認。
- 比較画面はPC、タブレット縦・横、スマートフォンの表示幅で確認。
- 本番DBのデータ操作・本番への配信は別途必要です。この変更による新規DBマイグレーション・Edge Functionの変更はありません。
