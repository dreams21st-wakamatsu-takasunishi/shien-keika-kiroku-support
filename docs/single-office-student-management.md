# Dレッスンの児童・ログイン管理（単一事業所運用）

## 日常の操作

Dサポートの「Dレッスン管理 → 児童・ログイン管理」を開く。

- 新しい児童はDサポートの児童名簿に登録してから、一覧の「Dレッスンに登録」を選ぶ。生年月日・氏名・共有の同意を確認して発行する。既存の学習IDがあるときは新規作成せず「アカウント連携」で本人を照合する。
- 児童番号はサーバーが重複を確認して採番する。新規登録先は若松高須西校に固定し、校舎選択はしない。
- 合言葉は新規発行・再設定分から数字6桁。空欄で自動生成するか、同じ6桁を2回入力して設定する。既存の合言葉は自動変更しない。
- 既存の合言葉は復号・一覧表示できない。既知の合言葉でログイン確認するか、忘れた場合に本人を確認して再設定する。再発行すると古い合言葉は使えなくなる。
- 発行結果が不明な場合は新規操作を繰り返さず「同じ操作の結果を再確認」。手動設定したときは最初と同じ合言葉を入力する。
- 「削除」は氏名を入力して確認する。ログイン用のデータアクセス権を停止し、一覧を「削除済み」に移す。Dサポートの名簿・学習履歴・Authアカウント・合言葉は消さない。
- 「削除済みを表示」から「復元」で元のアクセス権を戻す。本人・所属・権利関係が変わっていた場合は止める。

児童番号と合言葉の入力だけで、通常URLから教室へログインする。URLのcampus指定やブラウザに残る旧設定はログイン先選択に使わず、運用先のアカウント、従来の接頭辞なしアカウントの順に認証する。無関係な校舎へ自動移動・アカウント統合はしない。

## 権限・データ保持

管理一覧・削除・復元は、既存の学習連携管理とアカウント発行の両権限、および承認端末を必要とする。新たな一般職員の権限は付与しない。

校舎の追加・変更・削除と、Dレッスン単独での児童登録・合言葉再設定・完全削除の操作画面を廃止する。内部の校舎ID、過去の教材、所属、学習履歴は保持する。Dサポート上の既存リンクと本人確認の仕組みは残す。

削除中でもAuth自体は履歴保全のため保持するが、既存セッションを含め児童データのアクセス権を外す。復元すると同じ番号・合言葉で利用再開できる。アクセス権が複数児童・管理権限と共有されている場合や、合言葉発行が未完了の場合は削除を止める。

合言葉はログ・DB・ブラウザストレージに平文保存しない。手動設定時は操作に束縛したHMACのみ保持する。新規6桁自動生成は操作IDごとに安定した値を生成し、既存10桁発行の未確定操作は10桁のまま復旧できる。

## 公開順

1. 架空DBで `support_account_credentials.sql` と `support_student_admin.sql` を検証する。
2. Dレッスン側に上記SQLを適用。既存の児童・Auth・学習データは変更しない。
3. Dレッスン側の `support-account-credentials`、`support-student-admin`、`support-learning-read` をデプロイする。
4. Dサポート側の `lesson-account-credentials`、`lesson-student-admin`、`lesson-student-registration`、`lesson-learning` をデプロイする。
5. 両画面を公開し、公開資材の版・設定と匿名アクセス拒否を確認する。

公開だけでは実児童の削除・復元・合言葉再設定は実行しない。既存の本校に残る確認用データも移動・統合しない。
